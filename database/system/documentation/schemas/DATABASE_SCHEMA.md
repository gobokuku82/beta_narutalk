# 데이터베이스 스키마 문서

## 개요
본 시스템은 5개의 SQLite 데이터베이스로 구성되어 있으며, 인사 관리, 영업 실적 추적, 거래처 관리를 위한 통합 데이터 시스템입니다.

## 데이터베이스 구조

### 1. HR 데이터베이스 (`hr_data.db`)
**경로**: `database/hr_information/hr_data.db`

#### 테이블: 인사자료
직원의 개인정보와 급여, 평가 정보를 관리하는 핵심 테이블

| 컬럼명 | 타입 | NULL 허용 | 설명 |
|--------|------|----------|------|
| 사번 | TEXT | YES | 직원 고유 식별 번호 |
| 성명 | TEXT | YES | 직원 이름 |
| 본부 | TEXT | YES | 소속 본부 |
| 직급 | TEXT | YES | 직급/직위 |
| 부서 | TEXT | YES | 소속 부서 |
| 지점 | TEXT | YES | 근무 지점 |
| 연락처 | TEXT | YES | 개인 연락처 |
| 월평균사용예산 | REAL | YES | 월 평균 사용 예산 |
| 최근 평가 | TEXT | YES | 최근 인사 평가 결과 |
| 기본급(₩) | TEXT | YES | 기본 급여 (원화) |
| 성과급(₩) | TEXT | YES | 성과급 (원화) |
| 책임업무 | TEXT | YES | 담당 업무 설명 |

**데이터 규모**: 80개 레코드

#### 테이블: 지점연락처
지점별 연락처 정보를 관리

| 컬럼명 | 타입 | NULL 허용 | 설명 |
|--------|------|----------|------|
| 본부 | TEXT | YES | 본부명 |
| 부서 | TEXT | YES | 부서명 |
| 지점 | TEXT | YES | 지점명 |
| 지점 연락처 | TEXT | YES | 지점 대표 연락처 |

**데이터 규모**: 14개 레코드

---

### 2. 영업 실적 데이터베이스 (`sales_performance_db.db`)
**경로**: `database/sales_performance_db/sales_performance_db.db`

#### 테이블: sales_performance
월별 영업 실적을 추적하는 시계열 데이터 테이블

| 컬럼명 | 타입 | NULL 허용 | 설명 |
|--------|------|----------|------|
| 사번 | TEXT | YES | 영업 직원 ID |
| 담당자 | TEXT | YES | 담당자 이름 |
| 거래처ID | TEXT | YES | 거래처 고유 ID |
| 품목 | TEXT | YES | 판매 품목 |
| 202212~202411 | INTEGER | YES | 월별 매출액 (2022년 12월~2024년 11월) |

**특징**:
- 24개월간의 월별 매출 데이터 관리
- 각 월별 컬럼은 YYYYMM 형식 (예: 202401 = 2024년 1월)
- **데이터 규모**: 1,711개 레코드

## 데이터베이스 간 관계

### 주요 관계 매핑

1. **인사자료.사번** ↔ **sales_performance.사번**
   - 직원의 영업 실적 추적

2. **sales_performance.거래처ID** ↔ **거래처자료.거래처ID** ↔ **거래처정보.ID**
   - 거래처별 상세 정보 연결

3. **인사자료.지점** ↔ **지점연락처.지점** ↔ **지점별목표.지점**
   - 지점별 관리 체계

4. **인사자료.성명/sales_performance.담당자** ↔ **거래처자료.담당자** ↔ **지점별목표.담당자**
   - 담당자별 업무 추적

## 데이터 특성 및 주의사항

### 인코딩
- 모든 데이터베이스는 UTF-8 인코딩 사용
- 한글 컬럼명 및 데이터 포함

### NULL 처리
- 모든 필드가 NULL 허용으로 설정됨
- 데이터 입력 시 필수 필드 검증 필요

### Primary Key
- 현재 명시적인 Primary Key 설정 없음
- 향후 데이터 무결성 강화를 위해 PK 설정 권장:
  - 인사자료: 사번
  - 거래처정보: ID
  - sales_performance: (사번, 거래처ID, 품목) 복합키

### 데이터 타입 개선 필요사항
- 급여 필드 (기본급, 성과급): TEXT → INTEGER
- 날짜/월 필드: 표준화된 DATE 타입 고려

## 권장 개선 사항

1. **Primary Key 설정**: 각 테이블에 적절한 기본 키 설정
2. **Foreign Key 제약**: 테이블 간 관계에 외래 키 제약 추가
3. **인덱스 생성**: 자주 조회되는 컬럼에 인덱스 추가
4. **데이터 타입 최적화**: 숫자 데이터는 적절한 숫자 타입으로 변경
5. **NOT NULL 제약**: 필수 필드에 NOT NULL 제약 추가
6. **정규화**: 중복 데이터 제거 및 테이블 정규화 검토
