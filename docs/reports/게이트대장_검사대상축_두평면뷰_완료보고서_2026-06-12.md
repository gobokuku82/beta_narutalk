# 완료보고서 — 게이트 대장 검사 대상 축 + 두 평면 뷰 (2026-06-12)

## 무엇을

오너 질문 **"데이터를 못 보는 cognitive·planning에 왜 게이트가 복잡하게 있나? system gate / execution gate가 구분되어야 하는 게 아닐까?"**의 답을 게이트 대장(43)에 박제하고 시각화에 반영했다.

답의 요지: cognitive·planning 게이트는 데이터가 아니라 **에이전트 언어**(LLM이 만든 layer 간 전달물)를 검사한다. LLM 출력은 불신 입력이고, 데이터를 못 보는 층일수록 자기 산출물이 틀려도 스스로 모르기 때문에 언어 게이트가 더 필요하다 (실증: e2e 파일럿의 '추천' 의도 계획 탈락 / 슬라이스 1의 `period:"all"` 날조). "system/execution 두 권 분리"는 비채택 — execution 입구 게이트(G09~G14)의 본질이 **접점**(언어의 약속 vs 데이터 현실 대조)이라 어느 권에도 깔끔히 안 들어가고 drift 위험만 2배.

## 왜

- 오너가 의도한 구분("에이전트 언어 = layer 간 전달물 / 실제 data")이 시스템에 실재하는데 대장에 암묵적이었음 → 명시 축으로 승격.
- "표가 진실, 그림은 생성물" 전략 그대로 — 표에 열 1개 추가하면 모든 그림·HTML이 따라온다.
