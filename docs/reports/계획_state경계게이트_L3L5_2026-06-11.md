# 계획 — state 경계 게이트 (L3 임계치 슬림 + L5 미러 제거) · 2026-06-11

> 근거: [근본원인_execution_state_raw누수_2026-06-11.md](근본원인_execution_state_raw누수_2026-06-11.md) v2 (소비자 전수 감사 완료).
> 본질: 성능 패치가 아니라 **제어 평면(state/checkpoint) 입구에 빠져 있던 문지기 설치** — tool/data 분리 원칙의 강제 장치. (게이트 > 컨벤션 기대)

---

## 1. 스코프

| 포함 | 내용 |
|---|---|
| **L3** | `_build_execution_result` 산출(= state `execution_result` 채널 진입분)에 **크기 임계치 슬림** — 값 >256KB → 참조 스텁 치환 |
| **L5** | `execution_stage` 최종 Command에서 `execution_progress` 미러 **쓰기 제거** (읽는 곳 0 — 감사 §7.2-3) |

| 제외 (사유 박제) | |
|---|---|
| L3b: pause interrupt payload(`get_progress_snapshot`) 슬림 | **restore 경로가 full data 필요** — 서버재시작+resume 시 snapshot→completed_todos→previous_results 로 남은 todo 체이닝. 슬림하면 스텁(dict, non-empty)이 게이트를 통과해 normalizer 에 쓰레기 입력 가능. pause 중 비대는 transient + 사용자 액션 필요 → 후속. |
| L4: collector 참조 반환 | 후속(거대 2종 안전 확정). 본 게이트가 먼저 깔리면 L4 는 RAM 최적화로 격하. |
| 기존 비대 checkpoint 2개 정리 | 별도 (삭제 or 방치 — 대화이력 삭제 버튼으로 사용자가 지울 수 있음) |

## 2. 설계

### 2.1 신규 모듈 — `backend/app/dream_agent/execution/state_guard.py`
```python
STATE_VALUE_MAX_BYTES = 256 * 1024   # 임계치 (settings override 가능하게 getattr)

def approx_json_size(v, budget) -> int   # 조기탈출 재귀 추정기 — 104MB 를 dumps 안 하고 O(budget) 판정
def slim_execution_result(er: dict) -> dict  # todos[*].data 의 각 top-level 값 검사 → 초과 시 스텁 치환
```
- **스텁**: `{"_state_guard": "slimmed", "key": k, "size_bytes_approx": n, "where": "data 레이어(창고)에서 직접 조회 — state 비저장 정책"}`
- 슬림 발생 시 `logger.warning("state_guard slimmed", todo_id, key, size)` — **관측**(다음 누수는 로그 한 줄로 보임).
- 순수 함수 · 결정론 · in-place 아님(새 dict) — 원본(hitl completed_todos)은 불변.

### 2.2 적용 지점 (단 1곳)
[execution_stage._build_execution_result](../../backend/app/dream_agent/execution/execution_stage.py#L318) 끝: `return slim_execution_result(result.model_dump(mode="json"))`
→ 호출처 3곳(정상 종료·cancel·빈 plan) 전부 자동 커버. **in-memory 체이닝(hitl completed_todos → previous_results)은 건드리지 않음** — 리뷰 체인·게이트 무영향.

### 2.3 L5 — 같은 파일 [L294-300](../../backend/app/dream_agent/execution/execution_stage.py#L294)
`update={"execution_result": ..., "execution_progress": ...}` → `execution_progress` 키 제거. (state 채널 선언은 유지 — 미사용 채널, 회귀 0)

## 3. 영향 분석 (감사 근거)

| 소비자 | 받는 것 | 영향 |
|---|---|---|
| responder (`_render_metrics`/`_find_artifact`/`_collect_attachments`) | 스칼라·문자열·경로 (<임계치) | 0 — 스텁은 dict 라 `_render_metrics` 가 원래 스킵 |
| 데이터 게이트 (consumes) | in-memory previous_results | 0 — 슬림은 state 사본만 |
| 리뷰 체인 (raw_reviews→…) | in-memory previous_results | 0 — 동일 |
| recovery `detect_recovery` | `reason: data_insufficient` 소형 dict | 0 |
| WS node_event/complete → 프론트 | 슬림된 execution_result | **~312MB → KB** (개선) |
| layer_inspector | todos status | 0 |
| conversation_manager (대화이력) | user_input·response·overall_status | 0 — **신규 턴 checkpoint 155MB→KB → 복원 ms** |
| pause/resume·서버재시작 복원 | interrupt payload (불변) | 0 — L3b 제외라 |
