## 1. 항목 ② — layer guard "success" 어휘 drift (`33b48c1`)

**버그**: [layer_inspector.py:91]이 존재하지 않는 status `"success"`를 비교(실제 TodoStatus enum = completed/failed/skipped). succeeded가 항상 0 → **todo 1개만 실패해도 EXECUTION_ALL_FAILED(fatal)로 turn 전체 abort** + "모든 Todo 실행이 실패했습니다" 허위 메시지. PARTIAL_FAILED(warning) 분기는 도달 불가 데드코드.

**잠복 이력**: spec 20 §3.3이 **2026-05-15에 문서화**("백엔드 수정 필요 — 사용자 결정 대기") 후 약 1개월 방치. 그 사이 루트 logs/layer_guard.jsonl에 06-10 실발화 기록(12개 중 1 실패 → ALL_FAILED). 단위테스트 LG-04도 같은 "success" 픽스처라 동어반복 GREEN — **테스트가 drift를 영속화**하던 상태. "감지에 소유자가 없으면 썩는다" 부류의 대표 사례.

**수정 내역**:
| 항목 | 내용 |
|---|---|
| 어휘 | `"success"` → `"completed"` + detail에 skipped_count 추가 |
| 동반 수리 1 | summarize_state brand — targets 중첩 반영 (inspect 쪽은 06-10에 고쳐졌으나 요약 함수에 잔존한 사본 버그 → JSONL의 brand가 영구 null이던 것 해소, 페어 누적 brand 축 복구) |
| 동반 수리 2 | `_LOG_PATH` CWD 상대경로 → 리포 루트 절대경로 고정 (실행 위치에 따라 페어 로그가 루트/backend 두 파일로 분열되던 문제 해소. CWD 무관 해석 실측 검증) |
| 동반 수리 3 | conftest **autouse 격리 픽스처** — 테스트의 실그래프 실행이 프로덕션 페어 파일을 오염시키지 않도록 전역 tmp 우회 (과거 backend/logs 사본 100% 픽스처 오염의 재발 방지) |
| 테스트 | LG-04/LG-06 픽스처 어휘 교정 + **LG-03b 신설**(11 completed + 1 failed → PARTIAL warning, ALL_FAILED 격상 금지 — 06-10 실발화 재현 박제) + summarize 중첩 brand 회귀 |

**효과**: 부분 실패 시 턴이 죽지 않고 warning으로 계속 진행 → response가 부분 결과 + 실패 고지를 표시할 수 있게 됨(항목 ③과 연결). 기준질문 **G4**(부분실패 정직)의 백엔드 전제 충족.

## 2. 항목 ③ — FAILED의 거짓 성공 표시 2경로 차단 (`9323414`)

**경로 1 (responder)**: overall FAILED인데 완료 산출이 0이면 text fallback이 **"분석을 완료했습니다."** — 실패가 성공 문구로 둔갑. 수정: 실패 고지를 먼저("분석 중 일부 단계가 실패했습니다 (완료 N · 실패 M · 중단 지점: t_x)"), 부분 산출이 있으면 그 뒤에 보존 표시. **ResponsePayload.error 필드 첫 배선**(스키마에 있었으나 설정처 0이던 필드 — 2차 재분석 무소비 신호 목록의 1건 해소).

**경로 2 (ws_agent)**: cognitive/planning이 `Command(update={error}, goto=END)`로 끝나면 **complete(status=success) + 화면 무표시**("무언의 성공") — 2차 재분석 high 발견. 수정: `LAYER_ERROR` 코드 신설(error_codes.py 카탈로그 + spec 22 등재) → error 이벤트(stage 에러 메시지 포함) + `complete(aborted, reason=LAYER_ERROR)`.

**테스트**: 2c-9(FAILED+산출0 → 성공 문구 금지 + error 필드), 2c-9b(부분 산출 → 실패 고지 선행 + 결과 보존) 신설.
