## 1. 무엇인가 (한 줄)

**/monthly(월간 결산)의 KPI 카드 9개**에 마우스를 올리면 ✨ 버튼이 나타나고, 클릭하면
그 카드의 숫자를 스코프로 **에이전트에게 정형화된 질문**(진단·추천·재검증)을 한 번의 클릭으로 보낸다.
질문·답변은 일반 채팅과 동일하게 **checkpoint에 박제 → 대화이력에서 회상** 가능.

## 2. 사용자 관점 — 화면에서 어떻게 동작하나

```
① 카드 우상단 모서리에 [에이전트] 필 버튼 — **항상 표시**, primary 채움 (v2~v3: 오너 피드백)
② [에이전트] 클릭      → 팝업 메뉴 즉시
   ┌────────────────────────────────┐
   │ 전체 ROAS  0.30×                │ ← 컨텍스트 칩: 카드가 보여주는 값 그대로
   │ 2026-04 · methodology §S004 …  │    (지표·값·기간 = 송신 내용과 동일 / §S 는 참고 표시)
   ├────────────────────────────────┤
   │ ▸ 왜 이런지 분석 (진단)          │ 활성
   │ ▸ 개선안 추천                   │ 활성
   │ ▸ 재검증 (재계산 확인)           │ 활성
   │ ▸ 숫자 나온 방법 (예정)          │ 비활성 — P5 methodology_explainer 후
   │ ▸ 해줘 (MVP)                    │ 비활성 — 실 광고 API 연동 후
   │ ▸ 직접 묻기                     │ 채팅 패널만 열림 (자유 질문)
   └────────────────────────────────┘
③ 항목 클릭            → 팝업 닫힘 + 채팅 패널 자동 열림 + 사용자 질문 버블 즉시 (빈 대기 금지)
④ 에이전트 4-layer 실행 → 답변 스트리밍
⑤ 자동 박제            → 대화이력에 "[전체 ROAS 0.30× · 2026-04] 왜…" 로 남음 → 클릭 복원 가능
```

- 카드 **전체 클릭이 아니라 ✨만** 트리거 — 기존 인터랙션(tooltip ⓘ, 차트 hover)과 충돌 0.
- 데이터 **로딩 중이거나 값이 '-'면 ✨가 아예 안 뜸** (빈 값으로 질문하는 것 방지).
- 에이전트가 **이미 작업 중이면** 송신하지 않고 toast로 "작업 중입니다" 안내 (동시 turn 방지).

## 3. 메뉴별로 무엇이 보내지고, 어디로 라우팅되나

문구는 임의가 아니라 **라우팅 테스트(corpus_card_actions.yaml)로 검증된 표현**이다 — cognitive가
이 문구를 읽고 의도(operation)를 분류하므로, 표현이 라우팅을 결정한다(P3 = 백엔드 변경 0의 비밀).

| 메뉴 | 보내는 문구 (템플릿) | cognitive operation | task → tool |
|---|---|---|---|
| 왜 이런지 분석 (진단) | `{기간} {지표}이(가) {값}인데 왜 이런지 원인 분석해줘` | diagnose | CAUSAL_ANALYSIS → `diagnoser` (LLM 해설) |
| 개선안 추천 | `{지표} {값}의 개선안을 추천해줘` | recommend | RECOMMENDATION → `recommender` (planner short-circuit) |
| 재검증 (재계산 확인) | `{기간} {지표}을 재계산해서 {값}이 맞는지 검증해줘` | measure | METRIC_CALCULATION → metric tool 재실행 |
| 숫자 나온 방법 | (비활성) | — | 테스트에서 measure로 오분류됨 → **P5 methodology_explainer 필요 실증** |
| 해줘 | (비활성) | — | MVP+ (실행 액션은 실 광고 API 후) |
| 직접 묻기 | (송신 없음 — 패널만 열림) | 사용자 자유 입력 → cognitive 판단 | 풀 4-layer |

배선 근거: [intent_shim.py](../../backend/app/dream_agent/cognitive/intent_shim.py)(operation→TaskType 순수함수) + planner short-circuit. 상세 = doc 39 §3.

## 4. 내부 구조 — 부품 3개

```
[KpiGrid.tsx]  카드 9개의 데이터 보유처 (label·value·period·§S 산식 META)
     │  KpiCell 이 CardAsk 로 감쌈 (1곳 수정 → 9 카드 전부)
     ▼
[CardAsk.tsx]  ✨ 트리거 + 팝업 UI (컨텍스트 칩 + 액션 6) + 실패 toast
     │  askAgent({prompt, client, context})
     ▼
[actions.ts]   askAgent seam — 채팅 입력창과 동일한 송신 절차를 코드로 노출
     │  sendQuery (WS)
     ▼
[백엔드 4-layer]  cognitive → planning → execution → response  (변경 0)
```

### 4.1 `features/agent/actions.ts` — askAgent (송신 엔진)

```ts
askAgent({ prompt, client, context? }) → { ok: true } | { ok: false, reason }
```

- **가드 4종** (채팅 입력창 handleSend와 동일 규칙 — 일관성):
  | reason | 조건 |
  |---|---|
  | `not_connected` | WS 미연결 |
  | `no_client` | client 미해석 (호출 컴포넌트가 `useCurrentClient()`로 전달 — 해석 규칙 중복 금지) |
  | `busy` | 턴 실행 중 (turnId 있음 + 미완료 + 비일시정지) |
  | `send_failed` | WS 송신 실패 |
- **컨텍스트 임베드**: `buildUserInput` 이 `[지표 값 · 기간] 질문` 형태로 user_input에 접두.
  이유 둘 — ① 라우팅 테스트에서 발견된 **period 미바인딩 gap**의 해법(기간이 질문에 실려 cognitive가 읽음)
  ② checkpoint에 그대로 저장되어 **대화이력 회상 시 무엇을 물었는지 보존**.
- 성공 시 절차: `startTurn`(턴ID 발급) → execution/agent store 리셋 → 사용자 버블 추가 →
  `sendQuery`(WS) → **채팅 패널 자동 열림**.

### 4.2 `features/agent/CardAsk.tsx` — ✨ 팝업 (표시 + 선택)

- 사용법: 카드를 감싸기만 하면 됨 —
  ```tsx
  <CardAsk context={{ metric, value, period, methodology?, formula?, sub? }} disabled={loading}>
    <원래카드 />
  </CardAsk>
  ```
- 컨텍스트 칩 = `context` 표시 (지표·**값**·기간·§S). 이 중 **에이전트에 실제 송신되는 건 지표·값·기간**
  (user_input 임베드 — §4.1)이고, §S·산식은 사용자 참고용 표시(송신 X — **P5 methodology_explainer 에서 활용 예정**).
- 아이콘은 emoji 대신 **lucide** (BarChart3·Lightbulb·CheckCheck·Search·Zap·MessageSquare) —
  디자인시스템(액센트 1개·"AI 만든 티" 금지) 정합.
- 실패 시 `toast.warning` 으로 사유 안내 (silent 실패 금지).

### 4.3 `features/monthly/KpiGrid.tsx` — 배선 (P3)

- `KpiCell` 한 곳에서 wrap → **KPI 9개 전부** 자동 부착. `disabled = loading || value === '-'`.
- 카드↔pipeline 매핑 (P0 결과, [계획서 §8](카드클릭_에이전트연결_설계계획_2026-06-10.md) 표):
  K01 매출 · K02 마케팅비 · K03 ROAS · K04 CAC · K05/K06 프로모션 · K07 신규회원 · K08 AOV · K09 가입전환율.
  컨텍스트 칩 데이터는 KpiGrid 가 이미 가진 것(META §S + label/value/period) 재사용 — **추가 fetch 0**.

## 5. 왜 이렇게 설계됐나 (핵심 결정 3)

1. **문구 유도 = 백엔드 0** — 메뉴가 곧 검증된 한국어 표현. cognitive가 분류하므로 새 경로/API 불요.
   (P4에서 explicit operation 주입으로 정밀화 예정 — 문구 의존 제거.)
2. **신뢰 루프** — 값은 카드(=pipeline 정답값)가 제공하고, 에이전트의 LLM은 해설만.
   "LLM은 숫자를 계산하지 않는다"가 이 기능의 차별점 (설계 §1).
3. **저장은 공짜** — 각 액션 = 일반 턴 = checkpoint 자동 박제 → 별도 저장 코드 0, 대화이력·회상과 자동 연동.

## 6. 새 카드/페이지에 다는 법 (확장 가이드 — P6)

1. 카드 컴포넌트에서 표시 중인 `label · value · period`(+ 있으면 §S)를 `CardContext`로 모은다.
2. `<CardAsk context={...} disabled={loading}>` 로 감싼다. 끝.
3. 주의: value는 **표시 포맷 그대로**(예: '0.30×') — 사용자가 본 것과 질문이 일치해야 신뢰.
4. 표 행/차트 데이터포인트에 달 때는 ✨ 위치만 조정 (계획서 §9-4 미결정 — 행끝/dot).
