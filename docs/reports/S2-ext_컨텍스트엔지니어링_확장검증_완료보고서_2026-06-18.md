> **한 줄**: 오너 지시("계획서 더 보완 + 테스트·검증 더")에 따라 — 검증 중 **실측으로 두 진짜 갭(G-A·G-B)**을 발견, TDD 로 빨간불 세운 뒤 닫음. ②축(데이터 이해) 배선을 execution LLM **5종 전부**로 확장.

## 1. 무엇을 (What)
S1~S3(insight_extractor·summary_generator 배선)에서 멈췄던 ②축 의미 배선을, **검증을 강화하던 중 드러난 갭을 따라** 다음으로 확장:
1. **G-A 배선 확장** — diagnoser·forecaster(canonical 키 직수신, insight 와 동일 패턴인데 누락)·report_writer(지표정의만)에 데이터 사전 주입.
2. **G-B 구조 갭 폐쇄** — 함정 단위 키(ctr/cpc/ad_cost/roas)가 `rows[]` 안에 중첩돼 top-level 전용 사전을 **통째로 우회**하던 것을 1-depth nested 스캔으로 닫음.
3. **검증 2층 신설** — 규약 가드 + 커버리지 가드(드리프트 빨간불) + 주입 4종 회귀.

## 2. 왜 (Why)
- 오너 본 목표 = **할루시 ②축(LLM이 단위·함정을 못 받아 숫자 오독)** 근본 수정. S1~S3는 첫 슬라이스(2종)였고, **'왜/예측' LLM(diagnoser·forecaster)이 같은 벌거벗은 입력을 받는데 빠져 있었음**(G-A).
- 더 결정적: 단위 함정이 있는 키들(ctr=%·cpc=원·ad_cost=salesAmt함정)이 **전부 tool 산출 `rows[]` 중첩 안**에 있어, top-level만 보던 사전이 **구조적으로 못 닿았다**(G-B). S4(후속)로 미뤘던 것이 사실 1-depth 스캔이면 지금 닫히는 갭.

## 5. 정직 경고 (과신 금지)
1. **여전히 미측정** — 프롬프트에 사전이 들어간 것만 검증. "할루시가 실제 줄었나"는 **C2(라이브 e2e) 전까지 증거 없음**. (직전 보고서 §9.2 그대로 유효.)
2. **G-B 의 600자 size 가드 상호작용** — collect_inputs 가 큰 rows 를 *먼저* 떨군다. 그 경우 LLM 도 못 보므로 오독 위험은 없으나(일관), "큰 rows 를 통째 못 보는" 별도 ②축 부수 갭은 잔존(S4 영역).
3. **report_writer 가치 제한** — 칼럼 사전은 비고 metric_glossary(ROAS=배수 등)만. 입력이 해석된 텍스트라 본질적 한계.
4. **새 게이트 0 · 데이터레이어/프롬프트 한정** — 가드레일 정합. 게이트 코드는 손대지 않음(Phase B 측정 후).
