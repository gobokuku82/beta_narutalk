## 3. silent-0 — 거짓 보고서가 지어지는 연쇄

```
리뷰/해당 데이터 0건
  → insight_extractor (LLM): 빈 입력에도 호출 → 엉성한 insights 지어냄   [미수정 — 문2]
  → report_writer     (LLM): 빈 insights 받아도 호출 → "그럴듯한 보고서" 통째 지어냄  ★거짓의 정체
  → responder: 그 보고서를 "성공"으로 받아 사용자에게 전달
```
- 글을 *지어낸* 곳 = **report_writer** ([report_writer.py:53](../../backend/app/dream_agent/tools/report/report_writer.py#L53), execution LLM tool). response의 LLM도, insight tool도 아님.
- 원인 = **깨진 데이터 계약**: report_writer가 (a)리뷰3키만 읽고 (b)빈 가드 없고 (c)consumes 미선언이라 게이트가 못 막음.

## 4. R1이 고친 것 (현 상태 — 커밋 575aa84)

```
[수정 후] 데이터 0건 → 게이트(report_writer.consumes=[insights]) → 빈 입력 SKIP
            → report_writer 실행 안 함(거짓 보고서 X)
            → "data_insufficient" 구조화 신호 발생  ← 복구가 받을 신호
            → responder: build_insufficient_data_payload → 정직 "데이터 없음" 메시지
```
- G1 빈 가드 [report_writer.py:34](../../backend/app/dream_agent/tools/report/report_writer.py#L34) + G2 게이트 배선(consumes) + G3 orphan 제거.
- **남은 문2**: insight_extractor·summary_generator는 같은 패턴 미수정. **근본수정 후보** = `LLMTool` 공통 부모가 "빈 입력 → LLM 전 멈춤"을 자동화(새 LLM tool 자동 안전).

## 5. 복구(G6) 흐름 — ★간소화 확정 (2026-06-08)

```
[감지] execution 끝 → detect_recovery (그 기간 데이터 0건이면 모든 tool SKIP) → 막힘 감지
[메뉴] interrupt("데이터 없음. 다음 행동?  [다른 기간] [대상 변경] [중단]")   ← actions.yaml(설정)
[전송] ws_agent(송신)/ws_hitl(수신) 2통로. turn_id 키·payload 무관 → 3번째 통로 불요
[선택] 사용자 "3월"
[재실행] period param만 3월로 변경(기존 todo_modify 인프라) → resume → 같은 plan 재실행
            ▲ cognitive·planning 안 거침! (param 변경이지 재이해/재선택 아님)
```

**★핵심 정정(2026-06-08)**: 재실행에 **cognitive 재진입 불요**.
- cognitive는 user_input만 읽고 structured_query를 무조건 재생성 → goto=cognitive면 period 조정이 *덮어쓰임* ([cognitive_stage.py:138](../../backend/app/dream_agent/cognitive/cognitive_stage.py#L138), test H1).
- "다른 기간 재실행"은 질문·도구가 같고 **period 값 하나만** 바뀜 → 기존 HITL 편집([hitl_manager.handle_todo_edit](../../backend/app/dream_agent/workflow_managers/hitl_manager/manager.py#L410))이 이미 하는 "param 변경 → cascade 무효화 → 재실행".
- cognitive가 필요한 건 *완전히 다른 질문*일 때뿐 = 그건 복구가 아니라 새 turn.

## 6. HITL 인프라 (조사 확정 — test_hitl_layer_architecture)

- `interrupt()` **node-agnostic** (langgraph 1.1.6, 어느 레이어든). HITL은 이미 **planning(plan_review)+execution(pause)** 멀티레이어 — "execution 전용" 아님.
- 통로 2개 = **레이어별이 아니라 송신/수신 분리**. resume은 **turn_id 키·payload 무관** → 새 타입(data_recovery)도 **분기만** 추가(3통로 X). checkpointer 필수(런타임 AsyncPostgresSaver).
