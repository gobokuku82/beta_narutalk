## §0 시스템 개발론 → 에이전트 개발론 매핑

에이전트 개발은 시스템 개발론 위에 올라타는 구조다.  
기반 개념 없이 에이전트부터 배우면 직관으로 맞는 방향을 잡아도 경계와 계약이 빠진다.

| 시스템 개발론 개념 | 에이전트/하네스에서 역할 | 네 시스템 현황 |
|---|---|---|
| 관심사 분리 (SoC) | 4 layer 경계 | ⚠️ 경계는 있으나 권한 미결 |
| Design by Contract | tool 입출력 계약 | ❌ 계약 없음 → 게이트 28개 |
| State Machine | current_phase 관리 | ❌ state에 위치+데이터 혼재 |
| 단일 책임 (SRP) | 각 layer/manager 역할 | ⚠️ execution이 데이터플로 떠안음 |
| 방어적 프로그래밍 | 게이트·검증 | ⚠️ 계약 없이 사후 게이트로 때움 |
| Blackboard Architecture | tool 간 데이터 전달 | ❌ 4갈래 제각각 |
| Repository 패턴 | data layer 조회 | ✅ ADR-031 구현됨 |
| Working Memory | ArtifactStore (임시 저장소) | 🔧 ⚠️ Workspace 실재(데이터레이어용)·분석결과 workflow 저장소만 부재 |

## §2 컨텍스트 엔지니어링

**정의**: LLM이 추론할 때 보는 토큰을 무엇으로 채울지의 설계.  
메타데이터가 원천, 컨텍스트가 전달 방법.

```
메타데이터 없으면  →  컨텍스트에 뭘 넣을지 모름
컨텍스트 없으면   →  LLM이 메타데이터가 있어도 볼 수가 없음
```

### 컨텍스트 3 레이어

| 레이어 | 내용 | 누가 만드는가 | 현황 |
|---|---|---|---|
| 시스템 프롬프트 | 역할·도메인 지식·판단 기준 | 개발자 (정적) | ⚠️ 있으나 정책 없음 |
| 히스토리 | 이전 tool들이 알아낸 것 요약 | 시스템 자동 누적 | 🔧 ⚠️ previous_results 실재(계약·요약 없음) |
| 현재 입력 | 지금 분석할 데이터 + 의미 | 각 tool (DataEnvelope) | 🔧 ⚠️ collected/preprocessed_data 실재(신분 없음) |

### 항목별 현황

| 항목 | 현황 (as-is) | 기준 (should-be) | 우선순위 |
|---|---|---|---|
| 계획 LLM 입력 | ✅ 3단 메뉴 잘 됨 | 보존 명문화 | — |
| **LLM tool 입력** | ⚠️ 무차별 키 스캔 + 절단 | 입력 투영 정책 C1·C2 | **1순위** |
| 무엇을 넣고 빼나 | ⚠️ 수기 denylist | 신분 기반 거름 D2 | **2순위** |
| 토큰 예산 | ❌ 무음 절단, 정책 0 | 예산 정책 C3 | 2순위 |
| **컨텍스트 누적** | 🔧 ⚠️ execution 내 todo→todo는 됨(previous_results)·planning→execution 의도 귀속만 단절 | 누적 계약 | **1순위** |

```python
class DataEnvelope(BaseModel):

```

## §3 하네스 세팅

**정의**: 모델 바깥의 비계 — 실행 루프·게이트·검증·HITL·layer 오케스트레이션.

### State 설계 — 현황과 기준

**현황 문제**
```
🔧 state에 위치 필드(current_phase)가 아예 없음 — 위치는 LangGraph 노드 라우팅이 암묵 관리
   실제 데이터(execution_result dict)는 state에 적재됨
    → tool 결과가 state에 쌓임 → state 비대 → state_guard 등장 (사후 방어)
   ※ "위치+데이터 혼재"가 아니라 "위치 부재 + execution_result 비대"
```

**기준**
```
state     = 위치(current_phase) + 참조(ID)만
데이터    = ArtifactStore (임시 저장소)
영구 저장 = PostgreSQL
```

**AgentState 기준 구조**
```python
class AgentState(BaseModel):
    # State Machine — 위치만
    current_phase: Literal[
        "COGNITIVE", "PLANNING",
        "EXECUTING", "INTERRUPTED", "DONE"
    ]
    # 참조만 — 실제 데이터는 ArtifactStore에
    workflow_id: str | None = None
    result_ids: list[str] = []
    current_tool_index: int = 0
    interrupt_flag: bool = False
    error: str | None = None

    class Config:
        extra = "forbid"  # state 비대 원천 차단
```

### 메모리 설계 — 3 저장소

| 저장소 | 역할 | 생명주기 | 현황 |
|---|---|---|---|
| PostgreSQL | 영구 저장 | 영구 | ✅ 있음 |
| Workspace (실재) | tool 산출 공유·캐시 | cross-workflow 영속 | 🔧 ✅ 단 데이터레이어용(raw/cleaned/computed) |
| ArtifactStore (분석결과용) | 분석 tool 결과 임시 저장 | workflow 단위 | 🔧 ❌ 부재 — 단 Workspace와 역할 갈라야(중복 금지) |
| AgentState | 위치 + 참조 | 노드 간 공유 | ⚠️ 비대 |

### 계약 설계 — 누락된 3개

| ContextContract | LLM 입력 표준 | ❌ 없음 → 무차별 투입 |

### 항목별 현황

| 항목 | 현황 (as-is) | 기준 (should-be) | 우선순위 |
|---|---|---|---|

## §9 map이 놓친 추가 점검 요소

근거 있는 누락만 (추측 아님):

1. **Cognitive→Planning 핵심 계약(`structured_query`)** — memory `project_cognitive_as_translator`: "Cognitive 출력 스키마 = 시스템 핵심 계약". `schemas/structured_query.py` 실재인데 map엔 *출력 계약* 점검 행 없음 ("계획 LLM 입력 ✅"은 입력 메뉴지 출력 계약 아님). **최우선 계약이 지도에서 빠짐.**
2. **Response layer 역할·표시 계약** — map은 execution 역할만 다룸. M1 표시수술이 일어난 곳·보존 대상인데 ✅로 뭉뚱그림. 책임 대장 대상.
3. **정직 degrade 계약** — 보존 목록 #5(불가침). 실패/degrade 행이 map에 없음.
4. **멀티스코프 천장** (같은 tool 다른 기간 — 첫 발견 승) — 멀티쿼리 다음 천장. 전달 계약에 스코프 키(D3) 행 없음.
5. **schema 진화/버전** — memory `project_extension_ease_priority`: JSONB+schema_version+Optional+append-only. DataEnvelope/계약 제안에 버전 행 없음 (POC 핵심 원칙 누락).
6. **관측(observability)** — 게이트 발동 관측(H3)·`/agent-observability`. "게이트 작동하나"에 숫자로 답하는 장치. map에 관측 행 없음.
7. **보존 목록 5(불가침) 미정렬** — §6 "건드리지 말 것"이 보존 목록 5와 부분만 일치 (닫힌메뉴+stub0, intent계약+sub_intents≥2 누락). 재설계 시 가장 위험한 영역인데 부분만 덮음.
