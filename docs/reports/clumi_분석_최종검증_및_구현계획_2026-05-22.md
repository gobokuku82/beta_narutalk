# Part 1. 최종 검증 결과 (3축)

| 검증 축 | 질문 | 결과 |
|---|---|---|
| ① 계산식 정확성 | 계산식이 제대로 되었는가 | ✅ **통과** — methodology 정답 17/17 일치, 계산식 46종 전부 산출 |
| ② 데이터 충족 | 계산식에 필요한 데이터가 있는가 | ✅ **통과** — 필요 파일 누락 0. S019·S020 만 mock 자체 한계 |
| ③ 정제방법 충족 | 그 계산식을 위한 정제방법이 있는가 | ✅ **통과** — 정제 10규칙이 횡단 이슈 10종 전부 커버 |

### 1.1 검증 ① — 계산식 정확성
- `methodology_calculations.md` 핵심 정량지표 정답표 ↔ 파이프라인 산출값 **17/17 일치** (총매출 119,539,660 · ROAS 6.53 · CAC 30,512 등).
- 계산식 헤더 46개 = 산출 46종 (미산출 0). 완전 계산 43종 + S019·S020(데이터 제약) + S057(정성).
- S028·S045·S069 는 정답표와 자릿수까지 완전 일치.

### 1.2 검증 ② — 데이터 충족
- 46 계산식의 `소스 파일` 명세 ↔ `data/clumi/` 21소스 대조 → **필요 파일 누락 0**.
- 필요 컬럼은 정확본 사전(771컬럼)으로 확인 — 누락 없음.
- 데이터 제약 2건: **S019**(프로필 방문 미수록) · **S020**(메시지 시작 미수록) — methodology 가 자체 명시한 mock 데이터셋의 한계이며, 정제·계산 *방법*의 결함이 아님.

### 1.3 검증 ③ — 정제방법 충족
- `methodology_cleaning.md` 정제 10규칙이 계산 전 필요한 횡단 이슈(활성주문·KST·채널정규화·광고비합산·GA4세션·카테고리분배·등급통일·UTM·비회원분리·회원누적) **10종 전부 1:1 커버**.
- 타입 캐스팅·Meta `action_type` 선택·ROAS 단위 통일은 계산식 내부 처리(methodology 의도).

→ **3축 모두 통과. 데이터 기반·정제·계산은 검증 완료 상태.**

# Part 3. 구현 계획 — 분석 결과 → 대시보드

목표(사용자 확인): **분석-시각화를 대시보드에 표현.** PPT·보고서 출력은 그 이후 단계.

### Phase A — 정성 해설 완성 (분석 마무리)
- **입력**: `methodology_insights.md`(25 해설 룰) + `campaign_scenario_2026_04.md` + 계산값 46종
- **작업**: 25개 해설 박스(원인 분석·세그먼트 해석·프로모션 4관점·액션플랜 등) 작성. 핵심 질문 "왜 매출 +50.5% 인데 신규 +1.4%?" 답변 포함
- **산출**: 해설 25 → analysis JSON 병합 → **S001~S069 전 산출물 완성** (정량 46 + 정성 23)
- **선행**: 없음 (즉시 가능)

### Phase B — 대시보드 데이터 계약
- **작업**: 69 산출물을 B:SPRING 10섹션 구조로 재배열 + frontend 소비용 JSON 스키마 확정
- **참조**: `데이터_시각화_구조_계획서` API 계약 · `methodology_visualization.md` 차트 규격
- **산출**: 섹션별·산출물별 구조화 JSON (차트 데이터·표·해설·KPI)

### Phase C — frontend 조사 + 대시보드 화면
- **C-1 조사**: 현 `frontend/` React 대시보드 구조 (페이지·컴포넌트·API·라우팅) 파악
- **C-2 매핑**: 10섹션 분석 ↔ 화면 — 차트 8 + 표 23 + 해설 28 + KPI 9 배치
- **C-3 구현**: methodology_visualization 색상·차트 규격 적용해 화면 구현
- **선행**: Phase A·B

### Phase D — 재사용 파이프라인 엔진 (후속·장기)
- 현 `pipeline.py` 는 *1회용 분석 스크립트*. `데이터_파이프라인_구조_계획서` §4 의 **재사용 엔진**(collect→raw→cleaned→computed, spec 기반, 변환 리포트, API 서빙)으로 일반화
- POC 검증된 정제·계산 로직을 엔진 모듈로 이식
- MVP 의 실 API 수집 연동 대비

### 권장 순서
```
Phase A (해설 25) ─┐
                   ├─▶ Phase C (대시보드 화면)
Phase B (데이터계약)┘
Phase D 는 대시보드 후 별도 트랙
```
→ A·B 는 병렬 가능. C 의 C-1(frontend 조사)은 A·B 와 무관하게 선착수 가능.
