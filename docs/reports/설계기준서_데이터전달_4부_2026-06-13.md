## 1부 — 데이터플로 계약 (신설 · 본진)

**D1. 산출물은 1급 시민 — 모든 tool 산출은 "장부(artifact ledger)"에 등기된다.**
장부 항목 = {이름, 스코프, 신분(D2), 단위·정의, 생산자(tool·todo_id), 위치(값 직접 or 창고 참조), 1줄 요약}.
- 근거: Dagster asset 사상("산출물이 1급, 작업은 수단"), Anthropic 경량 식별자(본체는 런타임 로딩), OpenLineage(생산 이벤트 기록)
- 현 위반: previous_results = 평면 dict. "이 값 어디서 왔지?"에 답할 기록 0 — dropped 둔갑의 토양
- 슬라이스: Pydantic `ArtifactEntry` 신설, executor가 todo 완료 시 등기 (기존 data dict는 병행 유지 — 점진)

**D2. 값의 신분 3분류 — answer(답) / working(작업메모) / internal(내부장치). 생산 시점에 tool이 선언한다.**
internal = 기존 `_`접두 관례의 정식 승격. working = 정제 부산물(dropped, before_count 류). 미선언 기본값 = working (보수적 — 답 둔갑 방지).
- 근거: MCP audience annotation("이 정보는 누구용인가"), Anthropic tool 설계 가이드("raw 내부 수치 대신 의미 컨텍스트")
- 현 위반: dropped=81이 무신분으로 LLM에 흘러 "회원 81명 이탈" 거짓 서사 (실사고 2026-06-12)
- 슬라이스: ArtifactEntry.kind 필드 + 시범 경로 tool들의 산출 분류 선언

**D3. 장부 키 = 이름 + 스코프 합성 (`revenue_total@2026-04`).**
같은 이름·다른 스코프 산출이 공존 가능해야 멀티쿼리의 다음 단계("4월 매출과 3월 ROAS")가 열린다.
- 근거: 학습판 §3-5 실측 — 현 구조는 "실행 가능, 구분 소비 불가"(첫 발견 승). 멀티쿼리 천장의 정확한 위치
- 현 위반: find_in_previous 첫 발견 승 — 두 번째 스코프 산출은 이름 평면에서 영원히 그늘
- 슬라이스: 키 합성 규칙만 정의 (실소비 전환은 후속 — 천장 해소는 별도 슬라이스)

**D4. 계약은 코드 옆에(co-location) — tool 산출 스키마는 tool 코드에 선언하고, 카탈로그는 생성물이다.**
- 근거: dbt model contracts(위반 산출물은 생산 시점 거부), Dagster 메타 co-location. 보존 4(메타 무결성)의 구조적 보장
- 현 위반: **카탈로그 2개 분열** — tools/catalog의 report_writer `produces: report_text`(구버전) vs team_catalog `report_markdown`(수정본). 같은 tool에 두 진실 (학습판 §2 신규 발견)
- 슬라이스: 시범 경로 tool들의 산출 선언을 코드로 옮기고 두 카탈로그의 해당 항목을 생성물로 갱신 — 동기 테스트(gate ledger 방식)로 drift RED

**D5. 본체는 창고에, 흐름에는 참조 — 임계 초과·행 데이터는 창고 저장 + 장부 참조.**
state_guard(256KB)·_dataref의 임시 발명을 정식 계약으로 승격. 참조는 장부 항목이므로 표시·LLM이 "쪽지"를 오해하지 않는다.
- 근거: Airflow XCom의 교훈(작은 값만, 큰 것은 위치 전달), Anthropic 멀티에이전트("외부 저장 + 경량 참조 핸드오프")
- 현 위반: 스텁이 ad-hoc dict라 표시가 데이터로 오인해 화면 노출 (표시품질 사고 ①)
- 슬라이스: ArtifactEntry.location(inline | warehouse{layer, key}) — responder는 location 보고 분기

**D6. 전달은 명시 — 전량 복사 주입을 장부 기반 명시 매핑으로 대체. 충돌의 무음 폐기 금지.**
- 근거: Actor 모델의 명시 수신 계약(차용), OpenAI handoff input_filter("전부 넘기기"→"골라 넘기기")
- 현 위반: _inject_prev_outputs가 상류 전 키를 setdefault 복사 — 충돌 승자(먼저 완료 순)가 어디에도 로그 안 됨. 200 tool에서 generic 키(count 등 — 이미 21종 중복) 무음 오바인딩 확률 ≈ 1
- 슬라이스: 시범 경로에서 주입을 장부 조회로 대체 + 충돌 시 경고 로그 (전면 대체는 점진)

**D7. 지표는 registry — 분자·분모·단위·grain을 1회 정의하고, tool은 재계산 대신 조회한다.**
- 근거: semantic layer 정설(dbt MetricFlow — "정의 변경이 전 소비처 자동 반영"), LLM 접지 정확도 +17~23%p 벤치마크
- 현 위반: ROAS가 3가지 값(6.53배/395%/393%)으로 동시 표출 — 분모 2종(aggregate_ad_cost 1,831만 vs daily_performance 2,657만) + 라벨 무맥락
- 슬라이스: **오너 결정 선행** — ROAS 분모 (ⓐ 1,831만 ⓑ 2,657만 ⓒ 둘 다 유효·라벨 구분). 결정 후 registry 1호 등재 (보류 중이던 "결정 1"이 여기로 흡수)

## 2부 — 컨텍스트 정책 (명문화 + 보완)

**C1. LLM 입력은 장부 투영 — 무차별 키 스캔 금지. 기본은 answer만, working/internal은 결정론 차단.**
- 근거: 12-factor agents F4, LangChain Isolate, Anthropic("라벨 없는 정보 덩어리가 위계 해석을 망침")
- 현 위반: insight/summary가 전 키 스캔 + 수기 denylist(_NOISE) — denylist에 없으면 통과 (dropped 사고의 직접 원인)
- 슬라이스: collect_inputs를 장부 투영으로 교체 (denylist 소멸)

**C2. LLM에 들어가는 수치는 의미 동봉 — 라벨·단위·출처와 함께.**
- 근거: Tagged Context Prompts 실증(hallucination 98.88% 제거, arXiv 2306.06085)
- 현 위반: 평면 {키: 값} json — 키 이름만으로 LLM이 의미 추측
- 슬라이스: 투영 시 ArtifactEntry의 정의·단위를 함께 직렬화

**C3. 토큰 예산 명문화 — 무음 절단 금지. 초과 시 우선순위 규칙 + 잘렸음을 로그.**
- 근거: Anthropic compaction 사상, 학습판 §3-3(현 [:3000] 절단 — 뒤쪽 키 무음 탈락)
- 슬라이스: 절단 발생 시 경고 로그부터 (예산 정책은 후속)

**C4. 오해석 대응 순서 = 입력 큐레이션 먼저, 프롬프트는 마지막.**
- 근거: Karpathy(컨텍스트 > 프롬프트), 본 시스템 실증(계획 프롬프트는 게이트와 함께 이미 100%)

**C5. 표시도 같은 장부의 소비자 — responder와 LLM이 같은 신분 규칙을 읽는다.**
- 현 위반: 표시 거름망(_RENDER_NOISE)과 LLM denylist(_NOISE)가 각자 수기 관리 — 한쪽 고치면 다른 쪽 누락
- 슬라이스: R1~R3(표시품질 수술)을 별도 구현하지 않고 **장부 소비로 흡수** — 계획_표시품질_오염수술의 R1·R3가 이 원칙의 파생물이 됨

## 3부 — 하네스 재편

**H1. 게이트는 계약의 파생물 — 신규 게이트는 계약 검증으로만 채용.**
- 근거: 업계 정설 "Contracts define expectations. Gates enforce them"(Ataccama), 헌법 §7 채용 3문항에 "어느 계약의 검증인가" 1문항 추가
**H2. 슬라이스마다 게이트 흡수 영향표 기록** — 어느 게이트가 계약 검증으로 흡수·축소되는지 (후보: G09·G13·G14의 silent-0 변종 방어 → D2 신분 계약 검증으로 통합 검토. MVP 게이트 감사의 입력)
**H3. 게이트 발동 관측** — 발동 카운터(layer_guard.jsonl 확장) → 대장에 발동 수 열. "게이트가 작동하나" 의문에 숫자로 답 (발동 0 게이트 = 과방어 심사 근거)
**H4. 보존 5 불가침** — 계획층 기전(계약·메뉴·수선 순서·메타 무결성·정직 degrade)은 이번 재설계의 비계가 아니라 토대 (학습판 §1 표)
**H5. 정직 원칙 유지** — 계약 위반 = 거부 + 시끄러운 실패 (헌법 D2). 계약이 생겨도 "보정해서 통과"는 금지
