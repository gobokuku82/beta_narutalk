## 2. 확장-축소 방식

### expand (진입점에 저장 추가 — tool 은 아직 저장, 무해 중복)
- **runner**: 이미 **fallback save** 보유([runner.py](../../backend/app/pipelines/runner.py)) — `if cache_key and not exists: save(clean, meta)`. tool 이 저장 중이라 지금은 skip. → tool save 제거 시 **자동으로 fallback 이 저장**. **meta 를 tool 의 `_meta` 로** 강화(ERD columns·formula 보존).
- **dashboard1 `_cached_or_run`**: **저장 안 함**(tool self-save 의존) → execute 후 `storage.save(layer, cache_key, clean, meta=result["_meta"], client=client)` **추가**.

### contract (tool self-save 제거 — 카테고리별)
- A·B tool: `get_default_workspace().save(...)` 줄 삭제. tool 은 result(+`_storage`·`_meta` 힌트) 만 반환 → 진입점이 (cache.layer, cache_key)에 저장.
- C tool(2): 중간 parquet 저장이라 진입점이 대체 안 함 → **저장 제거**(prod 미소비). 테스트는 "tool 저장" 단언 → 갱신.

## 3. 복잡점 / 결정 포인트

1. **메타 이관** — tool save 의 `meta`(ERD columns·formula)를 진입점 save 로. runner fallback 의 meta 를 `final_raw.get("_meta")` 로, dashboard1 은 `result.get("_meta")` 로.
2. **cleaned-중간 C 2개** — active_orders_filter·member_metrics_validator parquet 은 prod 미소비(테스트만). **결정**: 저장 제거 + 테스트 변경(권장) vs 예외로 둠. (이미 pyarrow 로 fail 중인 테스트들)
3. **tool-save 단언 테스트 재작성** (4 파일):
   - `test_active_orders_filter`(parquet/schema/roundtrip), `test_member_metrics_validator`(parquet/schema), `test_ad_cost_aggregator`(cleaned json/schema), `test_storage_backend`(workspace 단위 — 그대로 OK, tool 무관). → tool-save 단언을 **진입점-save 단언** 또는 **삭제**로.
4. **A/B 캐시 내용 변화** — tool 이 저장하던 *rich result* 대신 진입점이 *return dict* 저장. output_model.model_validate 는 둘 다 통과(extra ignore) → 값 동일. test_route H5(r1==r2) 유지.
