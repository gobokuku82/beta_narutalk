## 0. 핵심 변경 (helper-B)

**BaseTool 에 헬퍼 1개 추가** ([base_tool.py](../../backend/app/dream_agent/tools/base_tool.py)):
```python
def fetch(self, source_id: str, context: ExecutionContext) -> Any:
    """tool용 데이터 요청. client 는 context.client_id 에서 (tool 은 client 모름).
    진입점(API/runner/agent)이 ctx.client_id 를 설정. 없으면 명확히 실패(fail-fast)."""
    client = context.client_id
    if not client:
        raise ValueError(
            f"client 미지정: ExecutionContext.client_id 가 비어있음 "
            f"(진입점이 client 설정 필요). source_id={source_id!r}")
    return self.ds.get(client, source_id)
```
→ `self.ds.get(client, "X")` 의 **drop-in 대체** = `self.fetch("X", context)`.

## 1. 변경 패턴 3종

**패턴 A — 단순 (대부분 ~34 tool):** client 를 `ds.get` 에만 씀.
```python
# 전
client = merged.get("client", DEFAULT_CLIENT)   # ← 삭제
df = self.ds.get(client, "orders")              # ← 변경
# 후
df = self.fetch("orders", context)
```
+ 파일 상단 `DEFAULT_CLIENT = "clumi"` 삭제. (loader 래핑형도 동일: `load_X(self.ds.get(client,"X"))` → `load_X(self.fetch("X", context))`)

**패턴 B — analysis (5 tool):** ds.get + ml 둘 다 client 사용.
- 대상: `review_sentiment` · `review_keywords` · `creative_ai_axes` · `creative_fatigue` · `ai_recommendation` (※ `review_recent` 은 ml 없음 = 패턴 A)
```python
# 전
client = merged.get("client", DEFAULT_CLIENT)
reviews = load_reviews(self.ds.get(client, "reviews")).rows
result = await ml.analyze_sentiment([...], client=client)
# 후
reviews = load_reviews(self.fetch("reviews", context)).rows
result = await ml.analyze_sentiment([...], client=context.client_id)
```
(ml 호출 전 fetch 가 먼저 실행되어 client_id 검증됨 → ml 에 None 안 감)

**패턴 C — ad_cost_aggregator (1 tool, 특수):** 메타 f-string + 공유헬퍼.
- `f"data/{client}/raw/{info['source_id']}.*"` → `f"data/{context.client_id}/raw/..."` (메타 표시용)
- `ad_cost_helper(...)` 가 `ds.get(client, …)` 호출 → tool 이 `context.client_id` 를 helper 에 전달 (helper 시그니처는 유지).

## 7. ①.6 진입점 실행 절차 (2026-05-29 추가 — 신중)

> ①.1~①.5(tool 42개) + ①.6a(runner·pipeline API) **완료**. 남은 ①.6b·①.6c.

### ①.6b — dashboard1 API client 필수화 (golden)

- **코드:** `dashboard1.py` 의 `client: str = Query("clumi", …)` **20곳** → `Query(..., …)` (스크립트 `Query("clumi"`→`Query(...`).
- **테스트(함정):** `test_route.py` 가 20 엔드포인트를 **client 없이** 호출(Query 기본값 의존). 필수화 시 깨지므로 **각 호출에 `"client": "clumi"` 추가.**
  - 일반: `params={"period": PERIOD}` → `params={"period": PERIOD, "client": "clumi"}`.
  - MoM: `params={"a":…, "b":…}` → client 추가.
  - **무파라미터 호출**(grade-timeseries·age): `client.get(url)` → `client.get(url, params={"client":"clumi"})`.
  - ⚠️ **invalid-period 테스트**(`params={"period":"2026/04"}`, 기대 400): client 빠지면 **422**(필수 누락)가 400보다 먼저 → **client 추가 필수** 해야 400 유지.
  - **missing-period 테스트**(기대 422): client 추가해도 period 누락 → 여전히 422 (OK).
  - **`_catalog`**: client 파라미터 없는 메타 엔드포인트 → **건드리지 않음.**
- **검증:** golden 299 + 특히 `test_invalid_period→400` · `test_missing_period→422` · kpi/segment 20개 200+정답값.
- **참고:** 프론트(`useDashboard1Data`)는 이미 항상 `?client=` 전달 → production 안전. 이건 죽은 기본값 제거(일관성).

### ①.6c — 프론트 데이터 기반 기본값 (pnpm build)

- **TopBar fallback**: `?? (clients.find(c=>c.id==='clumi')?.id ?? clients[0]?.id ?? 'clumi')` → `?? (clients.find(c=>c.raw_count>0)?.id ?? clients[0]?.id)` (clumi 글자 제거, 데이터 있는 첫 client).
- **페이지 `?? 'clumi'`** (Channel·DashboardV1·Creative·Cost·Trend·Dashboard1) + `useDashboard1Data.ts`·`RefreshButton.tsx` 의 `DEFAULT_CLIENT='clumi'`: 결정 필요 — **(권장)** store(selectedClientId)가 clients 로드 시 기본 client 자동 선택 → 페이지는 store 만 읽고 `?? 'clumi'` 제거. (대안: 각 페이지 `?? clients[0]` — 분산 유지)
- **검증:** `pnpm -C frontend build` + 수동 client 전환.
