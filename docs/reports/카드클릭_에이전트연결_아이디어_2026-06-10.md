## 1. 핵심 컨셉 — "신뢰 루프"

```
카드 클릭 → 스코프 고정 → 정형 액션 칩(왜/드릴/무엇이바뀜) → 결정론 tool이 값 계산 → LLM은 해설만 → 근거 공개(계산식·출처) → HITL 승인
```

경쟁 제품(ThoughtSpot 우클릭→AI 액션 메뉴, Power BI 비주얼→Summarize, Amplitude 정형 액션 칩)의 공통 패턴 = **(1) 클릭 대상이 곧 에이전트 컨텍스트 스코프 / (2) explain·drill·what-changed 정형 액션 먼저 / (3) 같은 스레드 자유 follow-up.** OctorAD의 차별점 = **"LLM은 숫자를 계산하지 않는다"** — 값은 결정론 tool(`/api/dashboard1/*` 정답값)이 만들고 LLM은 해설만 → 마케터 최대 페인(데이터 불신)을 정면으로 침.

## 2. 리서치 근거 (출처 + 검증)

### 마케팅 분석가 페인포인트 (confirmed)
- **수작업·문제해결에 시간 절반+**: 퍼포먼스 마케터 78%가 시간의 21%+를 데이터 정제·트러블슈팅에, 85%가 제작보다 문제해결에 시간 소모 ([DemandScience](https://demandscience.com)).
- **데이터 과잉·단절**: 채널마다 대시보드 달라 "What is working?"에 답하기 어려움 ([Beasley](https://beasleydirect.com)).
- **분석이 의사결정에 안 닿음**: 분석 영향력 53%, 미사용 1순위 = 소스 간 불일치 + 접근 곤란 ([Gartner](https://www.gartner.com)).
- **예산 낭비**: 평균 마케팅 예산 25% 낭비, 66% 리더 "지표상 성공이 매출로 안 이어짐" ([DemandScience]).
- **맞는 지표 > 많은 지표**: 30억 검색 분석상 기초 지표가 압도, 정교한 어트리뷰션 거의 안 씀 ([Supermetrics](https://supermetrics.com)).
- *(illustrative, 검증 caveat)* 리포팅 데이터 신뢰 <15%([PPC Hero], 미확정) / 어트리뷰션 불신 82%([Branch 2025], **앱마케팅 한정**) / 리포트에 주 10~20h([HubSpot]).

### AI 신뢰 원칙 (어떻게 믿게 하나)
- **숫자는 결정론 tool, LLM은 해설** — "LLM does not do math"(Tableau Pulse). 환각 숫자가 최대 anti-pattern.
- **검증가능 중간표현 공개** — text-to-SQL 블랙박스 금지, "AI가 이해한 질의"(structured_query)·계산식 노출(ThoughtSpot 토큰, Amplitude/Looker "How was this calculated?").
- **provenance/citation** — 모든 주장에 출처 endpoint·methodology 첨부(Tableau "back outputs up with sources").
- **불확실성 정직** — 날 confidence% 금지(false precision), 범위+근거+다음행동. 과신은 오히려 무능해 보임.
- **HITL은 옵션 아님** — automation bias 방지. OctorAD `requireReview` 토글은 진짜 pre-execution 승인(경쟁사 "즉시 적용"과 차별).

### anti-pattern (신뢰 붕괴)
환각 숫자 · 블랙박스 · 날 confidence% · 불확실성 은폐 · 근거 없는 추천 · metric 정의 충돌(governance 부재) · 끊긴 lineage · catalog≠code drift(grep 메타로 동작 단정).

## 4. 관통 설계 원칙

1. **클릭=스코프 고정 + 정형 액션 칩 → 자유 대화** (3단). 카드 metric+값+period+target을 `askAgent(prompt, context)`로 자동 주입, 칩 3종(왜/드릴/무엇이바뀜)+단일권장 먼저, 같은 스레드 follow-up.
2. **LLM은 숫자 계산 안 함** — metrics/comparison tool이 값, `/api/dashboard1/*` 캐시 정답값(methodology 17/17)이 ground truth, LLM(insight/diagnoser/forecaster/report_writer)은 해설만. catalog≠code drift 주의(실호출 키 기준).
3. **신뢰 = 계산 공개 + provenance + HITL** — structured_query 읽기전용 노출 + 출처 citation + `requireReview` 실행 전 게이트. 불확실성은 범위+근거+다음행동.
4. **컨텍스트 전달 최소 배선** — `features/agent/actions.ts`에 `askAgent(prompt, context)` 한 곳 신설(handleSend 복제). 카드 데이터는 이미 페이지 컴포넌트 state에 있어 추가 fetch 0, 백엔드 변경 0(clientId만 전달, 값은 prompt 임베드).
5. **AI 만든 티 금지 + 초보자 적극 권장** — 클릭만 하면 평문 질문 자동 생성, 가치판단은 전문가 단일 권장(V3/HITL 게이트).
6. **POC 제약 정직** — 단일 client(clumi)+mock. ambitious는 '씨앗'으로만(conversation checkpoint는 이미 영속, memory 100% 캡처·skill 저장은 MVP+).

## 5. POC 우선 추천 (1차)

**quick-win 2 (#1 퍼널 병목, #2 이상치 진단) + core 1 (#5 근거 보기)**

이유:
- **배선 비용 최소** — `actions.ts`의 `askAgent()` 한 곳만 신설하면 셋 다 즉시 동작, 백엔드 변경 0. 트리거 컴포넌트(MetricChainStrip·LineChart dot·지표 셀)에 `onClick`만.
- **의존 tool 전부 implemented** — diagnoser·forecaster·insight_extractor·report_writer 모두 team_catalog 등재(mock 없이 실동작).
- **세 개가 합쳐지면 §1 신뢰 루프를 한 번에 증명** — 클릭→스코프→진단→근거공개(structured_query+methodology) — 마케터 최대 페인(문제해결 시간·데이터 불신)을 정면으로 치면서 "LLM은 계산 안 함"을 시연. `requireReview`로 HITL 무비용 결합.

ambitious(1분 리포트·출처 화해·skill 저장)는 memory 캡처/리포트 체인 안정화 후 2차.

### 배선 seam (공통)
```
카드 onClick → features/agent/actions.ts  askAgent(prompt, {client, metric, value, period, target})
  └ useChatPanel.open() + session.startTurn() + execution.reset() + agent.clearTurn()
    + agent.appendUserMessage([context] prompt) + sendQuery({conversationId, turnId, userInput, clientId})
```
현 `sendQuery`는 client_id만 전달 → 컨텍스트는 prompt 텍스트 임베드로 시작, 추후 query 메시지에 optional `context` 필드 추가 가능.

## 6. 검증 — 정직하게 (refuted/uncertain)

워크플로우 적대 검증이 잡은 정정 (단정 금지):
- ❌ **REFUTED**: "$400K 실패·채택률 12%/$50M SaaS" 일화 — insightsoftware 2026 설문에 없음(직접 fetch 확인). 그 설문의 실제값(신뢰 51%·환각우려 33%·pilot 통과 31%)만 인용. → §2 anti-pattern에서 그 일화 제외.
- ⚠️ **scope**: "어트리뷰션 불신 82%" = Branch 2025 **앱마케팅 한정**(전체 마케터 아님). "31% 확신"·"6+ tools"는 별개 설문(RevSure·Adverity).
- ⚠️ **overstated**: Amplitude가 "모든 행동 실행 전 인간 승인 강제"는 과장 — 자사 문서는 "즉시 적용". OctorAD `requireReview`만 진짜 pre-execution 게이트.
- ⚠️ **unverified(illustrative)**: PPC Hero "<15% 신뢰", RevSure 59%/46%, beasley "2주" — 출처는 실재하나 정확 수치 미확정. illustrative로만.
- ✏️ **scope fix**: DemandScience 87% = "조직의 87%"(지표의 87% 아님).
