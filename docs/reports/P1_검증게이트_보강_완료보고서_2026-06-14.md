## 1. 무엇을 했나

검증 리포트가 "8/8·12/12 PASS는 mock 우연, 실데이터면 침묵하며 틀린다"고 판정한 **3대 정직성 공백**을 게이트 코드로 메움. **산출물(데이터)은 안 건드리고, 검증 레이어만 추가**.

| P1 항목 | 신규/수정 | 한 일 |
|---|---|---|
| **C1·C2·C3** coverage | `coverage.py` (신규) | contract 44필드 status 매니페스트 + 정직 배지 + not_attempted 게이트 |
| **B3** crosswalk WARN | `verify_outputs.py` (수정) | PASS/FAIL 외 **WARN** 상태 도입 + `cross_channel_groups==0` 경고 검사 |
| **클러스터3** A1·A2 dict | `dict_gate.py` (신규) | 사전↔raw 실헤더↔contract 컬럼 **자동 diff** (탐지 전용) |
| 통합 | `gate.py` (신규) | materialize→4단 검사 일괄 + 종합 판정 단일 엔트리 |

## 2. 왜 (각 항목의 근본 문제)

- **coverage**: contract 44필드 중 ~13만 materialize·7만 tested인데 "verify 8/8 PASS"가 *contract-complete*처럼 읽힘. 미구현 ~31필드는 검사항목에 없어 **구조적으로 fail 불가**(vacuously green). → 배지로 분모를 정직하게 노출.
- **crosswalk WARN**: `cross_channel_groups=0`(C5 목적 0% 달성)인데 verify에 검사 0건 → '연결됨'처럼 materialize. → 매 실행 WARN으로 무용을 가시화.
- **dict gate**: deterministic 값검증은 '구현이 contract대로 raw 처리했나'만 봄 → 사전·contract *자체*의 정의 drift(사전 `stat_dt`/`camp_id`/`convCnt`가 raw에 부재, campaign_id 17 vs 18)를 **절대 못 잡음**. 값은 맞는데 정의가 틀린 침묵 오류. → 이름 존재성을 기계 대조.

- **coverage 정직 배지**: measure 9/16·metric 3/11·dim 1/15·time 0/2 materialized. tested 7(`ad_cost_krw`·`conversion_count`·`conversion_revenue_krw`·`mer`·`msg_cost_krw`·`order_revenue_krw`·`roas_x`).
- **dict_gate DRIFT 18 실측**(전부 직접 확인): naver 9(`stat_dt`/`camp_id`/`camp_name`/`convCnt`/`customer_id`/`device_tp`/`grp_id`/`kwd`/`kwd_id` — raw는 `statDt`/`nccCampaignId`/`ccnt`/`device` 등) · meta 4(`purchase`/`add_to_cart`/`purchase_value`/`roas` — raw는 EAV `actions[]`/`purchase_roas[]`) · orders 4(`customer_age_group`/`customer_gender`/`guest_email_hash`/`region`) · campaign_id 1(사전 17 vs raw 18).

### ⚠ 작업 중 잡은 내 거짓경보 2건 (정직 기록)
1. dict_gate 초판이 contract `campaign_id` dimension source의 **인라인 주석**(`"data[].campaign_id(18자리 — ...)"`)을 leaf로 못 떼서 CRITICAL 6 오판 → 괄호 제거로 수정 → CRITICAL 0(contract 실제 정상).
2. raw 추출기가 top-level+summary만 봐서 kakao `cid`·talktalk `total_friends`(중첩 섹션 실재)를 "사전 오기"로 오판(DRIFT 25) → 전체 재귀 추출로 수정 → DRIFT 18(진짜만).
→ **게이트가 늑대소년이 되지 않도록 두 번 자기검증.** raw 헤더는 보고서 신뢰가 아니라 직접 직독으로 확인.

## 5. 경계 (오너 영역 — 안 건드림)

- 사전(`clumi_data_dictionary.csv`)의 **계산내용/의미/formula 수정 = 오너 영역**(memory `project_data_viz_work_division`). dict_gate는 *이름 존재성*만 기계 판정하고 DRIFT를 **보고만**, 사전을 고치지 않음. DRIFT 해소(사전 재작성 vs raw 자동생성) 방향은 오너 결정.
- meta 4건 DRIFT는 "사전 오기"라기보다 *논리뷰 문서화*(EAV 평탄화)일 수 있음 — 판단은 오너.
