## 1. ②-a — 직접 읽기 제거 (clumi_loader · load_mock_csv)

### clumi_loader (file_no → `data/clumi/raw/{file}`, clumi 하드코딩)

data_sources(SOURCE_REGISTRY: source_id→파일명)와 **기능 중복**. file_no 대신 source_id 로 통일.

| tool | 사용 | 이관 |
|---|---|---|
| `missing_value_diagnostic` | `load_clumi_source(file_no)` | `self.fetch(source_id, context)` (file_no→source_id 매핑) |
| `grade_system_unifier` | `CLUMI_SOURCES` (file_no 매핑) | source_id 직접 |
| `kst_timezone_normalizer` | `stream_clumi_source(file_no)` | ⚠️ 스트리밍 (아래) |
| `ga4_session_aggregator` | `stream_clumi_source(file_no=8)` | ⚠️ **265MB jsonl 스트리밍** |
| `collection/_base` | `CLUMI_SOURCES` import | 확인 후 제거 |

**⚠️ 복잡점 (검토 필요):**
1. **file_no ↔ source_id 매핑 검증** — 파일명 대조 (예: 5→orders, 6→customers, 21→customer_grade_history.csv vs data_sources `grade_history` **파일명 불일치** 가능 → 확인 필수).
2. **스트리밍** — `ga4_page_events.jsonl` 265MB 는 `stream_clumi_source` 로 줄단위 처리. `DataSource.get` 은 **전체 로드**(스트리밍 미지원). → data_sources 에 `stream(client, source_id)` 추가 or ga4 별도. **결정 필요.**

### helpers.load_mock_csv (sprint15 collectors)

- 사용: `meta`·`kakao`·`naver_sa`·`naver_gfa`·`google_ads`·`review` collector.
- ⚠️ **이미 깨짐**(삭제된 mock 파일 참조) + **agent team_catalog·planning prompt·sprint15 테스트 결합**.
- → **별도 신중 단위**: 제거할지(agent 결합 추적) / 데이터 복구할지 **결정 필요**. golden 밖(sprint).

## 2. ②-b — 직접 저장 제거 (tool 순수화)

~30 tool 의 `get_default_workspace().save("computed"|"cleaned", key, result, meta=…)` 제거 → **저장은 진입점**(runner·dashboard1)이 단일 수행.

**⚠️ 복잡점 (①에서 확인된 것):**
1. **ERD 메타 이관** — tool save 의 `meta`(columns·formula·input_source)를 진입점 저장으로 옮겨야 ERD 표시 유지.
2. **tool-save 단언 테스트 재작성** — `test_active_orders_filter`(parquet/schema)·`test_member_metrics_validator`·`test_ad_cost_aggregator`·`test_storage_backend` 가 "tool 이 파일 저장"을 단언 → 진입점 저장 기준으로 변경.
3. **dashboard1 `_cached_or_run` 은 현재 저장 안 함**(tool self-save 의존) → 저장 추가 필요. runner 는 fallback save 있음.

**방식: 확장-축소(expand-contract)** — 진입점에 저장 추가(중복 무해) → tool self-save 카테고리별 제거 → 테스트 이관.
