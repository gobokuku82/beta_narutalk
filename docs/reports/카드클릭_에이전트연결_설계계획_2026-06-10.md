## 1. 컨셉 — 4 레이어 사다리 + 신뢰 루프

사용자 데이터분석 4 레이어 = doc 39의 시스템 "4 결" = 팝업 메뉴 항목, 셋이 1:1 정합:

| 사용자 레이어 | doc 39 결 | operation | tool |
|---|---|---|---|
| ① 정보(수집→정제→지표) | (대시보드가 이미 표시) | — | metrics |
| ② 분석(탐색→진단→추론→예측) | 분석 사다리 | measure/diagnose/attribute/forecast | metric·diagnoser·insight_extractor·forecaster |
| ③ 의사결정(옵션→시뮬→추천→승인) | 의사결정 | recommend | recommender + HITL |
| ④ 실행(운영·콘텐츠·소통·학습) | (산출/학습) | — | report_writer·대화이력 |

**신뢰 루프**: 클릭 → 스코프 고정 → 정형 액션 → **결정론 tool이 값 계산** → LLM은 해설만 → 근거 공개 → HITL. 차별점 = **"LLM은 숫자를 계산하지 않는다"**(값=`/api/dashboard1/*` 정답값, LLM=해설).

## 2. 인터랙션 설계 (확정)

### 2.1 트리거 + 팝업
```
┌──────────────────────────────────┐
│ 📊 객단가(AOV)  62,293원          │ ← 컨텍스트 칩 = 카드 데이터 = "스코프"
│    2026-04 · §S048 · 출처: orders │   (에이전트에 넘길 것과 동일 = 투명성)
├──────────────────────────────────┤
│ 🔍 숫자 나온 방법                 │ 결정론
│ ✅ 재검증 (재계산 확인)           │ 결정론
│ 📊 분석              ▸            │ 사다리(탐색/진단/추론/예측)
│ 💡 의사결정 추천                  │ recommender
│ ⚡ 해줘               [MVP]       │ 비활성
│ 💬 직접 묻기                      │ 자유 + 컨텍스트 고정
└──────────────────────────────────┘
```
- **트리거 = hover 시 `✨` affordance** (카드 우상단/표 행끝/차트 데이터포인트). 카드 전체 클릭 X → 기존 인터랙션(차트 hover·표 정렬) 충돌 0.
- **카드 데이터 표시 = 팝업 상단 컨텍스트 칩**({지표·값·기간·목표·§S}). 사용자가 "무엇을 묻는지" 확인 = 신뢰.

### 2.2 타이밍 — "빈 대기 절대 금지"
```
hover → ✨ 페이드인(150ms) → 클릭 → 팝오버 즉시
  → 항목 선택 → 팝오버 닫힘 + 채팅 패널 열림 + 사용자 질문 버블 즉시 + PhaseIndicator 진행  ← 응답 전에!
  → 에이전트 스트리밍 → 답변 + follow-up 칩 → 대화이력 자동 박제
```
- 🔍✅ 재검증은 "**검증 중...**"으로 프레이밍(느림 X = 꼼꼼함 → 신뢰).

## 4. 내부 연결 경로 (확정)

### 4.1 seam — `askAgent(prompt, context)` 신규 (`features/agent/actions.ts`)
`handleSend()` 복제: `useChatPanel.open()` + `session.startTurn()` + `execution.reset()` + `agent.clearTurn()` + `agent.appendUserMessage()` + `sendQuery({conversationId, turnId, userInput, clientId})`. 카드 데이터는 페이지 컴포넌트 state에 이미 있음 → 추가 fetch 0.

### 4.2 라우팅 깊이 = **tiered (explicit operation 주입)** — 4-layer 전부도, 새 경로도 아님
| 액션 | 통과 | 이유 |
|---|---|---|
| 🔍✅ | **planner short-circuit (thin)** | 결정론 — LLM 0 |
| 📊💡 | **cognitive 얕은 스킵**(operation hint → 결정론) + planning~execution | 메뉴가 operation 이미 앎 → LLM 분류·오분류 제거 |
| 💬 | **풀 4-layer** | 자유 NL → cognitive 분류 필요 |

### 4.3 cognitive-skip 안정장치 (확정)
cognitive를 건너뛰면 그 출력(`structured_query`)을 직접 구성 → **계약 검증 장치 필요**:
- **(a) 스키마 검증** — 만든 게 유효한 `StructuredQuery`인가 (주입 지점, 신규)
- **(b) fallback** — (a) 실패 시 풀 cognitive로 (신규)
- **(c) 다운스트림 게이트 보존** — coherence·validate_dag([planner.py](../../backend/app/dream_agent/planning/planner.py))·interpretation_fed([execution/data_gate.py](../../backend/app/dream_agent/execution/data_gate.py))는 **cognitive 아래에 살아서 그대로 돎** → 재구축 불요
- **(d) 메뉴 제약 = 안전마진** — operation 고정셋·metric/period 카드 실데이터 → garbage 구조 못 만듦
> 즉 신규는 (a)+(b)면 충분. "cognitive 출력과 비교"가 아니라 "**같은 계약 만족 검증**".

## 5. #1 `methodology_explainer` tool (확정)

"숫자 나온 방법"의 소스 = `backend/app/pipelines/flows/*.yaml` (52개). 예 `dashboard1_kpi_aov.yaml`:
```yaml
description: "객단가 KPI — 매출/주문수 (S048)"
methodology_id: M01   visualization_id: K08
steps: [{ tool: aov_monthly }]   cache: S048_aov_${period}.json
```
**계획**:
1. 카드가 **`visualization_id` 보유** (또는 매핑표)
2. tool이 viz_id → pipeline 역조회 → `{description, tool, §S methodology, 정답값(_catalog/캐시)}` **결정론 추출**
3. → **qa_responder RAG**(doc 39 "RAG hook 자리") — **팩트는 pipeline/§S에서만, LLM은 표현만**
4. **on-demand** 조회(쿼리 시 pipeline 읽기, drift 없음)
5. 카드 ≠ 1 pipeline인 경우(endpoint 조립·외부값) = **커버리지 갭 정직 표시**
- 결과: "AOV = 매출÷주문수(§S048), aov_monthly tool, orders 데이터, 4월 정답 62,293 · 재계산 일치 ✓"

## 6. 에이전트 동작 + 저장

- **동작**: 각 액션 = 한 턴 = cognitive(또는 스킵)→planning→execution→response. operation별 tool(§3).
- **저장(대화 트랙)**: 매 턴 = **checkpoint(octormate_system) 자동** → user_input에 카드 컨텍스트 임베드 보존 → **대화이력에 뜨고 회상 가능**(`[AOV 62,293 2026-04] 재검증`). 방금 구현한 대화이력·회상과 닫힘.
- **저장(학습 트랙)**: 카드-액션 패턴 → memory_entries = **MVP+**(현 0-byte). POC = checkpoint로 충분.

## 9. 미결정 (구현 중 확정)

1. **분석 4 서브** 지금 다 vs **진단부터**(권장) — 나머지 climb.
2. **🔍✅ 결정론** = REST 직접(즉시) vs **에이전트 thin turn**(회상 위해 turn 권장) — 둘 다 가능, turn 권장.
3. **explicit `operation` 필드**를 WS query 메시지에 추가하는 지점 (21 WEBSOCKET_PROTOCOL spec 정합).
4. ✨ affordance 위치 디테일 (KPI 카드 / 표 행 / 차트 dot 각각).
