## 1. 무엇을 — 폐지한 거짓말

```
오염원 tool: period 미지정 → "period": "all" 을 데이터로 방출
  → executor._inject_prev_outputs 가 하류 필수 param 으로 주입
    → cac_overall: signup_date.startswith("all") = 신규회원 0명
      → CAC = 0원, status = COMPLETED   ← 거짓 숫자가 '성공'으로
```

이 사슬을 **4겹 독립 방어**로 끊고, 종착을 정직 되묻기로 바꿈:

| 겹 | 위치 | 내용 |
|---|---|---|
| P1 주입 금지 | executor `_inject_prev_outputs` | `SCOPE_PARAMS{period, period_a, period_b}` 주입 금지 — 시간 스코프는 쿼리에서만 (R2). 오염원 5곳(ad_cost_total·channel_attribution/utm_normalizer·category_multi_distributor·member_guest_stats)의 'all' 라벨 방출도 폐지 |
| P2 경계 거부 | executor `_param_boundary_issue` (신설) | 필수 누락 → SKIPPED(missing_param) / 'all'·'2026-13'·비정형 → SKIPPED(invalid_param) — **거부, coerce 금지 (D2)**. + `validate_params` 실행 전 호출 배선(2026-06-01 설계의 미배선분) |
| P3 plan 자가평가 | planner `detect_plan_gaps` | 스코프 param 은 상류 artifact 로 충족 간주 금지 + catalog produces 의 period 제거 2곳(맹점의 원인) |
| P4 정직 되묻기 | responder 세 번째 결정론 게이트 (신설) | period SKIP → **"기간을 알려주세요 (예: 2026년 4월)"** — 자동 기본월 금지(D3), 부분 완료가 있어도 숫자 단정 안 함 |

## 2. 핵심 발견 — drift 정합이 한 묶음인 이유

코드가 period 를 강제(raise)하는 tool **17종** 중 카탈로그 `params_required: [period]` 선언은 2종뿐(06-11 정합분). 나머지는 **상류 'all' 주입에 우연히 기생**해서 돌고 있었음 → 주입만 끊으면 정상 쿼리(월 있는)도 깨짐. 그래서 **drift 정합 9곳**(cac_overall — G2 의 'CAC 0원' 직접 원인 — ·aov_monthly·grade_revenue·new_members_monthly·promotion_revenue·promotion_roas·repurchase_rate_mom·signup_conversion·unknown_revenue_share)을 같은 커밋에 묶음. 현재 period-required 13종 = 코드 grep 과 1:1.

부수 수리: `_resolved_month` 가 '2026-13'(월 범위) 통과·'2026-4'(zero-pad) 0건 매칭하던 구멍 → 범위 검증 + 정규화.
