# 데이터 → 대시보드 설계 워크벤치 — 계획서

> 작성일: 2026-06-21 · 대상 페이지: `시스템 → DB설계` (`/db-design`)

---

## 0. 한 줄 요약

**정형 raw 데이터(엑셀/DB)를 이해(ERD)하고, 무엇을 볼지(지표)를 설계해서, Claude Code 가 구현할 수 있는 "설계 명세"를 뽑는 워크벤치.**
이 페이지는 *설계/명세*까지 책임지고, *실제 구현(프론트·DB·쿼리)* 은 VSCode 의 Claude Code 가 한다.

---

## 1. 배경 & 문제 (왜 만드나)

- 사용자는 **다양한 raw 정형 데이터**(엑셀일 수도, 이미 DB 일 수도)를 가지고 있고, 이걸로 **분석 대시보드**를 만들고 싶다.
- 사용자는 **엑셀은 다루지만 SQL/코딩은 깊지 않다.** 엑셀을 보며 관계를 연구하는데, 머릿속 정리가 어렵다.
- **ERD 가 있으면** 데이터 구조·관계가 머릿속에 정리된다. (← 이미 해결됨)
- 그런데 **ERD 까지 만들고 나면 그다음을 모르겠다.** ERD 는 "데이터가 어떻게 생겼나"(구조)만 알려주고, 대시보드에 필요한 **"무엇을 볼까"(분석지표)** 는 빠져 있다. → 지금 흐릿함의 정체.
- 실제 구현은 **Claude Code(VSCode)** 가 해도 된다. 즉 런타임에 모든 게 한 시스템으로 이어질 필요가 없다. **부분부분 띄엄띄엄 OK.**

---

## 2. 정체성 & 경계

| 항목 | 내용 |
|---|---|
| **주인공** | 엑셀/정형데이터는 있지만, 분석 대시보드를 직접 못 만드는 실무자 |
| **결과물** | Claude Code 가 바로 구현 가능한 **설계 명세** (ERD/DDL + 지표 + 대시보드 정의) |
| **이 페이지의 책임** | ① 데이터 이해(ERD) · ② 지표 설계 · ③ 명세 산출 |
| **이 페이지 밖(다운스트림)** | 실제 DB 구축·데이터 적재·프론트 대시보드 구현 → **Claude Code** |
| **현재 범위 밖** | 런타임 AI 질의/RAG(개념 ②), 실데이터 차트 렌더링, BI 실행 |

> **핵심 원칙:** 엔진(ERD 모델·파서·DDL·지표 모델)은 **추상·범용**으로, 동선(주인공·결과물)은 **하나로 구체화**.

## 3. 전체 파이프라인

```
[raw 정형데이터: 엑셀 or 기존 DB]
        │
        ▼  ──────────── 이 페이지 (워크벤치) ────────────
   ① 데이터 이해   : 엑셀 가져오기 → ERD (구조·관계 파악)        ✅ 완료
   ② 지표 설계     : ERD 위에서 "무엇을 볼지" 정의 (집계/차원/차트)  ⬅ 신규 핵심
   ③ 명세 산출     : ERD + DDL + 지표 + 대시보드 → 통합 명세(JSON/MD)
        │
        ▼  ──────────── 핸드오프 ────────────
   [VSCode Claude Code]  명세를 읽어 → DB 구축 + 대시보드 프론트 + 쿼리 구현
```

---

## 4. 현재 상태 (이미 만든 것 — Phase 0 완료)

- **ERD 설계**: 테이블/칼럼(PK·NN·UQ·기본값) 생성·편집, FK 관계.
- **엑셀 가져오기**: 메시한 실무 엑셀 → 깔끔한 관계형 스키마
  - 헤더 자동 감지(혼합 계층/병합/제목행 대응)
  - 타입 추론, **가로→세로 언피벗**(월별 칼럼 → `기간/값`)
  - 공통 키 자동 FK(한글 키 포함), 누적 업로드
- **칼럼 단위 FK 연결** UX(캔버스 드래그 + 우측 패널 드롭다운)
- **DDL 출력**(PostgreSQL `CREATE TABLE`) + 설계 영속(`var/erd/*.json`)
- 단위 테스트 34개(파서/언피벗/자동FK) 통과

→ **파이프라인의 ① 데이터 이해는 사실상 완성.** 다음은 ② 지표 설계.

---

## 5. 핵심 신규 — 지표(Metric) 설계 레이어

ERD 가 "구조"라면, 지표는 "**이 구조로 무엇을 측정·표시할까**"다.

### 5.1 데이터 모델

```
Metric (지표 1개)
  id            : 고유 id
  name          : "거래처별 월 매출 추이"
  sourceTable   : 기준 테이블 (ERD 의 테이블)
  measure       : 집계 대상 칼럼 (예: 실적)
  aggregate     : SUM | COUNT | AVG | MIN | MAX | COUNT_DISTINCT | RATIO
  dimensions[]  : 묶음 축 (GROUP BY) — 칼럼 + (시간축이면 단위: 월/분기/년)
  filters[]     : 조건 (칼럼, 연산자, 값)  예: 년월 >= 202401
  chart         : line | bar | pie | kpi | table
  sort / limit  : 정렬·상위 N
  joins[]       : (선택) ERD FK 기반 조인 — 다른 테이블 칼럼을 차원으로

Dashboard (지표 묶음)
  name          : "영업 실적 대시보드"
  metrics[]     : Metric id 목록
  layout?       : (선택) 배치 힌트
```

### 5.2 예시 (사용자 데이터)

```
"거래처별 월 매출 추이"
  sourceTable = 실적
  aggregate   = SUM(실적)
  dimensions  = [거래처ID, 년월(월 단위)]
  filters     = [년월 >= 202401]
  chart       = line
  joins       = 실적.거래처ID → 거래처.거래처명  (이름으로 보기)
```

### 5.3 UI/UX (ERD 위에 얹기)

- ERD 캔버스 옆/아래에 **"지표" 탭** 또는 패널.
- 지표 빌더(폼):
  1. 테이블 선택 → 2. 집계+대상 칼럼 → 3. 차원(드래그/선택, 시간축 단위) → 4. 필터 → 5. 차트
- **ERD 연동**: 칼럼/조인 후보를 ERD(테이블·FK)에서 자동 추천 → 사용자는 고르기만.
- **미리보기**: 실데이터가 없으므로 *"이 지표는 이런 SQL/이런 차트가 됩니다"* 를 **설명 + 모형(목업)** 으로. (실데이터 차트는 범위 밖)
- 지표들을 **대시보드로 묶기**.

> 설계 철학: **폼 기반(가드레일)** 으로 비개발자도 만들되, 생성된 SQL 초안을 보여줘 학습/검토 가능하게.

## 6. 핸드오프 명세 포맷 (Claude Code 용)

이 페이지의 **최종 산출물 = 통합 명세 한 묶음.** Claude Code 가 읽고 구현한다.

```json
{
  "erd":   { "tables": [...], "fk": [...] },        // 구조
  "ddl":   "CREATE TABLE ...",                       // 즉시 실행용 SQL (이미 생성)
  "metrics":   [ { "name": "...", "aggregate": "...", "dimensions": [...], "chart": "..." } ],
  "dashboard": { "name": "...", "metrics": ["..."] },
  "intent":    "자연어 설명 — 이 대시보드의 목적/맥락"  // AI 구현 정확도 ↑
}
```

- **export 버튼**: 위 명세를 JSON/Markdown 으로 복사·다운로드 ("Claude Code 에 붙여넣기").
- Markdown 버전은 사람이 읽기 좋게(표/설명 포함) — Claude Code 가 컨텍스트로 받기 좋음.
- Claude Code 가 받으면: `CREATE TABLE` 실행 → 데이터 적재 가이드 → 각 지표를 **SQL 쿼리 + 차트 컴포넌트**로 구현.

## 7. 단계별 로드맵

| Phase | 내용 | 상태 |
|---|---|---|
| **0** | ERD + 엑셀 가져오기 + DDL + 칼럼 FK | ✅ 완료 |
| **1** | **지표 설계 레이어** (Metric 빌더 + Dashboard 묶기 + SQL 초안/목업 미리보기) | ⬅ 다음 |
| **2** | **통합 명세 export** (ERD+DDL+지표+대시보드 → JSON/MD, 복사 버튼) | 다음 |
| **3** | (선택) **기존 DB introspection** — 이미 DB 인 데이터 → ERD 역설계 입력 경로 | 후속 |
| **4** | (선택·미래) 실제 DB 적용/적재, 런타임 AI 질의(개념 ②) | 후속 |

---

## 8. 비범위 (이번엔 안 함)

- 실데이터로 차트를 **실제 렌더링**하는 BI 런타임 (Claude Code/다운스트림 몫)
- DDL 의 **실제 DB 실행**·데이터 적재 (검토 후 수동/Claude Code)
- 런타임 AI 에이전트 질의(개념 ②) — 미래 옵션

---

## 9. 미결 질문 (정하면 Phase 1 착수)

1. **명세 포맷**: JSON 위주? Markdown 위주? 둘 다?
2. **미리보기 수준**: SQL 초안 + 설명만? 아니면 가짜 데이터로 차트 목업까지?
3. **지표 빌더 수준**: 폼(가드레일) 전용? 아니면 "자유 SQL 직접 입력" 모드도?
4. **입력 경로**: 당분간 엑셀만? 기존 DB introspection(Phase 3)을 앞당길지?
5. **대시보드 배치(layout)**: 이번에 다룰지, 명세엔 지표 목록만 담고 배치는 Claude Code 에 맡길지?
