## 1. 한눈 요약 (컨셉)

> **`/db-design` = "데이터 → 대시보드 설계 워크벤치".**
> 정형 raw 데이터(엑셀/DB)를 **이해(ERD)** 하고, **무엇을 볼지(지표)** 설계해서, **Claude Code 가 구현할 명세**를 뽑는 곳.

- **주인공**: 엑셀은 알지만 SQL/코딩은 약한 실무자.
- **결과물**: Claude Code 가 바로 구현 가능한 설계 명세 (ERD/DDL + 지표 + 대시보드).
- **경계**: 이 페이지는 *설계/명세까지*. 실제 DB 구축·데이터 적재·대시보드 구현은 **Claude Code(다운스트림)**. 런타임 AI 질의는 범위 밖.
- **원칙**: 엔진(ERD모델·파서·DDL·지표모델)은 추상·범용, 동선(주인공·결과물)은 하나로 구체화. "한 페이지에 우겨넣지 않기."

```
[raw 정형데이터: 엑셀 or DB]
        │  ────────── 이 페이지 ──────────
   ① 데이터 이해   : 엑셀 가져오기 → ERD            ✅ 완료
   ② 지표 설계     : ERD 위에서 "무엇을 볼지" 정의   ⬅ 다음
   ③ 명세 산출     : ERD+DDL+지표 → JSON/MD 명세
        │  ────────── 핸드오프 ──────────
   [VSCode Claude Code]  명세 → 대시보드 프론트 + DB + 쿼리 구현
```

## 2. 개념 기초 (비전공자용) — 엑셀 ↔ DB

이 절은 "SQL/DB 저장 방식"을 엑셀에서 출발해 설명. (사용자 학습 정리)

### 2.1 DB 저장 방식 = "엑셀 시트 여러 장"
- **DB 표 1개 = 엑셀 시트 1장** (행=레코드, 열=필드). DB = 작은 시트 여러 장의 묶음. 특별한 마법 없음.

### 2.2 연결(FK) = 엑셀의 **VLOOKUP**
- 엑셀: `담당자` 시트 따로 두고 `VLOOKUP(사번)` 으로 이름 끌어옴.
- **DB의 FK = 그 VLOOKUP을 영구적으로 박아둔 것.** 사번 = "담당자 시트를 찾아가는 열쇠". ERD 화살표 = "이 칼럼으로 저 시트를 VLOOKUP".

### 2.3 "엑셀 → DB" = 쪼개고 ID로 연결 (합치는 게 아님)
- ❌ 오해: 엑셀들을 하나로 **합친다**.
- ✅ 실제: 엑셀 1개 = 주제 1개 = **표 1개.** 표끼리 **공통 키로 잇는다.** 반복 정보는 ID(열쇠)만 남김.

```
Before(엑셀 1시트): 정예준이 매 줄 반복
  사번      담당자  거래처ID   품목    202212 202301 …
  MR-01022  정예준  강서…      가스몬  55473  27101

After(DB 여러 시트):
  [담당자] 사번→담당자 (사람 1명=1줄)
  [거래처] 거래처ID→거래처명
  [실적]   사번  거래처ID  품목  년월   금액   ← 월은 세로(언피벗), 이름 대신 ID만
           MR-01022  강서…  가스몬  202212  55473
```

### 2.4 DB는 합친 모습을 **저장하지 않는다 → "조립"한다**
- 엑셀 = **굳은 스냅샷**(합친 결과를 그대로 저장). 바꾸려면 반복분 다 손봄.
- DB = **부품(작은 표)만 저장.** 합친 모습은 질문할 때 **JOIN(여러 VLOOKUP 동시)** 으로 **그때그때 조립**하고 버림.
- → **부품 한 곳만 고치면** 다음 조립부터 자동 반영. (진짜 "살아있는" 건 DB)

```
[부품: 작은 표들] ─질문→ [JOIN으로 조립] → [답 한 장] → (버림)
   ↑영구 저장              ↑매번 새로          ↑임시
```

### 2.5 정규화 = 반복 제거
- 정예준이 100줄 반복(엑셀) → 이름 바뀌면 100줄 수정. DB는 담당자 1줄만 수정.

### 2.6 팩트 + 차원 (스타 스키마) — "실적이 여러 군데로 이어지는" 이유
- **실적 = 팩트**(측정값). 한 줄 = "누가·어디·무엇·언제 → 얼마".
- **차원 = 그 맥락**: 담당자(사번)·거래처·품목·시간(년월).
- 팩트가 차원들로 뻗음 → 그래서 실적이 여러 군데로 연결됨(=팩트의 특징, 정상).

```
   담당자(사번🔑)        거래처(거래처ID🔑)
        ▲ 사번                ▲ 거래처ID
        └──────┐      ┌───────┘
            실적(팩트)  사번🔗 거래처ID🔗 품목🔗 년월 금액
                 │ 품목
                 ▼
            품목(품목🔑)
```

### 2.7 언피벗(가로→세로) — 월별 칼럼 처리
- `202212…202411`(가로 24칼럼)은 엔티티가 아니라 **시간 축** → **세로로 펼침**: `년월` 칼럼 + `금액` 칼럼.
- 월을 별도 테이블로 만들지 않음. (예외: 고급 "날짜 차원 테이블"은 지금 불필요)

## 3. 지금까지 만든 것 (Phase 0 완료)

### 3.1 기능
| 기능 | 설명 |
|---|---|
| ERD 설계 | 테이블/칼럼(PK·NN·UQ·기본값) 생성·편집, FK 관계, DDL(PostgreSQL) 출력, 영속 |
| **엑셀 가져오기** | 메시한 실무 엑셀 → 깔끔한 관계형 스키마 (여러 개 한번에/누적) |
| ├ 헤더 자동감지 v2 | 병합 기반 다단(계층) 헤더, 제목행·혼합계층 대응, 데이터행 오염 방지 |
| ├ 타입 추론 | 데이터 샘플링 → INTEGER/DATE/BOOLEAN/VARCHAR 등 |
| ├ **언피벗** | 연속 기간 칼럼(202212…) 감지 → `[년월, 값]` 으로 접기 |
| ├ 자동 FK | 공통 키 이름 매칭(`xxx_id` + 한글 키 `사번·거래처ID·품목`) → FK 자동 연결 |
| **칼럼 단위 FK 연결** | 캔버스 칼럼↔칼럼 드래그 / 우측 패널 🔗 드롭다운(기존 칼럼에 직접 지정) |

### 3.2 기술 상세 & 주요 버그 픽스 (참고)
- **헤더감지**: 가로 병합만/top-anchored/contiguous 로 다단 헤더 인식 (월 텍스트·숫자 무관).
- **언피벗**: 그룹 접두사 다르면(실적/목표) 별개 런; 값 타입은 base 칼럼 타입 widening(소수 절단 방지).
- **자동 FK**: 단일 PK 후보만, 후보 1개일 때만 연결(모호성 방지), 한글 일반명 가드.
- **React Flow 엣지 (3중 픽스)**:
  1. 노드 통째 교체가 매 store 변경마다 `handleBounds` 초기화 → 엣지가 노드 중앙으로 떠버림 → **in-place 노드 병합**(measured 보존)으로 해결.
  2. `useUpdateNodeInternals` 로 칼럼 핸들 재측정.
  3. 투명 핸들이 카드 밖 ~7px 삐져나가 **엣지가 칼럼에서 7px 떨어짐** → 핸들 transform 의 가로 이동 제거(`translateY(-50%)`)로 **딱 붙게** 함. (Playwright 실측으로 확정: gap +7px → ±1.4px)
- **renameTable**: 이름 변경 시 그 테이블을 참조하던 FK 의 table 명도 갱신(끊김 방지).
- **테스트**: 35개 통과 (헤더감지 H1–H13 · 언피벗 U1–U11 · 자동FK F1–F9 · removeTable/renameTable). tsc·lint·빌드 클린.

## 4. 다음 (Phase 1+) — "지표 발견기" + "차원 추출 도우미"

### 4.1 지표(metric) = 차트가 아니라 작은 선언 객체
- 모든 시맨틱 레이어(Looker·Cube·dbt·Metabase·Power BI)가 같은 어휘를 씀 → **그 어휘를 그대로 명세로 쓰면 Claude Code 가 즉시 인식**.
- 구조: `집계(SUM/COUNT/AVG…) × 칼럼` + `차원[](GROUP BY, 시간단위)` + `필터[]` + `차트` + `정렬/limit`.
- `base`(집계) + `derived{비율·수식·성장률 MoM/YoY}` 면 비즈니스 ~90% 커버.

### 4.2 핵심 통찰: "어떤 지표가 필요한지 모름"이 정상 → 도구가 **발견**해줘야 — ✅ Phase 1b 완료 (2026-06-21)
- 빈 폼에서 발명 ❌ → **데이터 모양에서 후보 지표 자동 제안 → 사용자가 고르고 다듬기** ✅.
- 후보는 **데이터 구조에서 규칙적으로** 나옴(AI 없이도): 숫자 1개→KPI, ×시간→추이, ×범주→Top-N, ×작은범주→비중, ×시간비교→성장률.
- = **"지표 빌더"가 아니라 "지표 발견기".**
- **구현**: `metrics.ts` `suggestMetrics(tables)` — 팩트(측정값+차원/시간) 분류 후 측정값마다 KPI·추이(line)·Top-N(bar)·차원×시간(line)·성장(LAG bar) 후보 생성. `metricToSql` 로 SQL 초안(식별자 큰따옴표=SQLite/PG공통) → **빌드된 DB(Phase 1a)에 바로 실행**해 실제 숫자 확인(루프 닫힘). 시간축 오탐 방지(월방문횟수·월평균사용예산=측정값). UI=`MetricDiscoveryDialog`(좌 후보목록 / 우 SQL+실행), 페이지 "지표 발견" 버튼. 실스키마 42후보, 테스트 12.

### 4.3 사용자 아이디어의 정답 버전: **차원 추출 도우미** — ✅ Phase 1a 완료 (2026-06-21)
- "월별 하위칼럼을 테이블로" ❌ → 월은 언피벗(이미 있음).
- 대신: 실적의 **키 칼럼(거래처ID/사번/품목)** 을 보고 → *"거래처 마스터로 빼서 연결할까요?"* 제안 → **별도 마스터 테이블 자동 생성 + FK**. (= 정규화 자동화)
  - 마스터 엑셀 따로 있으면 → 가져와 자동 FK (Phase 0)
  - 마스터 없으면 → **마스터를 *구조 수준*으로 생성**(PK `<키>` + `<마스터>명` 칼럼 자리) + 팩트에 FK.
    실제 *고유값 적재는 안 함* — 이 페이지는 설계/명세 범위, 적재는 다운스트림 SQL `INSERT … SELECT DISTINCT`.
- **구현**: 두 경로 —
  1. **도우미(자동)**: 키처럼 보이는 칼럼(`거래처ID`·`품목코드`·`_id`) 또는 기존 단일-PK 마스터와 일치하는 칼럼을 훑어 일괄 제안(생성/연결 배지) → 고른 항목 적용. (`DimensionHelperDialog`, 페이지 "차원 추출" 버튼)
  2. **수동(패널)**: 이름만으로 안 잡히는 키(`사번`·`품목`)는 우측 패널 칼럼별 `⇲ 차원` 버튼으로 직접 추출.
- **로직/파일**: `dimensions.ts`(`suggestDimensions`·`deriveMasterName`·`isKeyLike`) + store `applyDimensions`(순수)·`extractDimension`·`applyDimensionSuggestions`. 테스트 54개(차원 19↑).
- **탐지 휴리스틱**: 키 접미사(`_id`/`id`/`코드`/`번호`/`키`) → 생성, 기존 마스터 PK명 일치 → 연결, 일반 속성(`담당자`)·일반명(`코드`)은 제외(노이즈 방지), 같은 키는 한 제안으로 묶음(여러 테이블 동시 연결).

### 4.4 핸드오프 명세 (Claude Code 용)
- **하이브리드** `dashboard-spec.md`(의도/맥락 prose) + fenced JSON 계약(ERD·DDL·metrics·dashboard) + 형제 `spec.json`.
- 각 지표에 `id`·`sqlDraft`·`intent` 포함 → 코드젠 정확도↑. `layout: null`(배치는 Claude Code).

## 5. 정보구조(IA) — 가이드 허브 + 3 스포크 (확정)

> 한 페이지에 안 우겨넣기 + 비개발자 친화 → **가이드형 허브-앤-스포크.**

```
[프로젝트 허브: 진행도 + 명세 개요]
   ├─ 스포크1 데이터/ERD (현 /db-design, 완료체크: 테이블≥1+FK)
   ├─ 스포크2 지표 빌더 (옆에 ERD 미니맵)
   └─ 스포크3 명세 export
   (진행도는 보이되 자유 이동 — ERD↔지표 반복 편집 지원)
```
